## 1. 目的

**図面** の TIFF ファイルの中から、図面の一部として描かれている **構成表** (欄外左上に「構成表」と書かれた表) を見つけ、表の中の文字を読み取って、**Excel に表としてそのまま貼り付けられる形** で出力する。

- Excel への貼り付け自体は手動でよい。
- 読み取った結果は、人が目で確認する前提とする (OCR の誤りはゼロにならない)。

## 2. 絶対条件 (制約)

| No | 条件 | 内容 |
|---|---|---|
| C-1 | **外部通信の禁止** | 実行中は一切の外部通信をしない。クラウド OCR、Web API、テレメトリ、自動更新、オンラインの辞書やモデル取得はすべて禁止 |
| C-2 | **ローカル完結** | 画像の読み込みから出力まで、すべて手元の PC の中で完結させる |
| C-3 | 使う技術 | 表と罫線の検出は OpenCV、文字の読み取りは Tesseract OCR |
| C-4 | 言語 | 日本語と英数字が混ざった表を読めること (Tesseract の `jpn` と `eng`) |

C-1 の実装方法と検証方法は「9. 外部通信の禁止」に書く。

# wheels フォルダを持ち込んで、対象 PC で

## 4. 入力仕様

### 4.1 入力は図面

入力の TIFF は **図面ファイル** で、構成表は図面の一部として描かれている。そのため、普通の書類と違って次のものが同じ画像に入っている。表の検出と表題の読み取りは、これらに惑わされないように作る (7.4 と 5.2)。

| 図面にあるもの | 表の検出への影響 |
|---|---|
| 図枠 (図面の外周の枠線) | 一番大きな四角。構成表や表題欄が図枠の線にくっついていることが多い |
| 表題欄 (図番・図名などの欄) | 構成表と同じく罫線付きの表。構成表とくっついていることがある |
| 改訂欄など、他の表 | 罫線付きの表 |
| 部品の形、寸法線、中心線、引出線 | 縦線・横線・斜線・円。罫線と間違えるおそれ |
| 寸法の数字、注記 | 表題と間違えるおそれ。注記に「構成表」という言葉が出ることもある |

### 4.2 ファイルの仕様

| 項目 | 仕様 |
|---|---|
| ファイル形式 | TIFF (`.tif` / `.tiff`) |
| ページ数 | 複数ページ (マルチページ) に対応する |
| 色 | 白黒 2 値 (FAX 形式の CCITT Group4 圧縮を含む)、グレースケール、カラー、16bit |
| 解像度 | ファイルの DPI 情報を使う。無いか 50 未満のときは 300dpi とみなす |
| 推奨解像度 | 300dpi 以上 (200dpi では読み間違いが増えることを試作で確認) |
| 傾き | ±5 度までの傾きを自動で補正する |
| 用紙の大きさ | A4〜A0 を想定。A0 を 400dpi で読むと約 18,700 × 13,200 px (グレースケールで約 250MB) になる |
| 対象の表 | **罫線で区切られた表** (罫線の無い表は第一段階の対象外) |

### 読み込みの注意

- Pillow の `ImageSequence` で全ページを読む。FAX 形式の圧縮も Pillow で読める。
- 16bit 画像は `L` に変換すると白飛びするので、配列にしてから 0〜255 に正規化する。

## 5. 対象の表の特定 (表題「構成表」)

### 5.1 前提

- 構成表は図面の一部として描かれている。
- 対象の表の表題は **欄外左上** にあり、「**構成表**」と書かれている。**前後に括弧は無い。**
- 欄外 = 表の枠線の外。左上 = 表のすぐ上で、左寄り。

### 5.2 表題を読む範囲

表ごとに、次の範囲だけを読む。

| 方向 | 範囲 |
|---|---|
| 上端 | 表の上端から 0.8 インチ上 (300dpi で 240px) |
| 下端 | 表の上端の少し上 (dpi/100 px 上) |
| 左端 | 表の左端から 0.3 インチ左 |
| 右端 | 表の左端から「表の幅の半分」か「1.5 インチ」の大きい方まで |

さらに次の処理をする。

1. 範囲の中に別の表の横罫線があれば、それより下だけを見る (上にある別の表の文字を拾わないため)。
2. 罫線と点ゴミを消す。
3. 文字の行 (帯) を上から順に探し、**表に一番近い 1 行だけ** を読む。
   - 図面の注記などに「構成表」という言葉があっても、表題として拾わないため。
   - 表の上にある寸法線や部品の形の線は、文字の行と間違えないよう、行の高さが文字の大きさとして不自然なもの (高さ 1.5mm 未満、15mm 超) を除く。
4. その 1 行を Tesseract で読む (「8. セルの文字の読み取り」と同じ前処理)。

### 5.3 一致の判定

- 読んだ文字と探す文字を、両方とも次のように正規化してから比べる。
  - Unicode の NFKC 正規化 (全角と半角の違いを無くす。「（」→「(」)
  - 空白をすべて取る
- 探す文字は **「構成表」** とし、読んだ文字に含まれていれば一致とする。
  - 完全一致にしない理由: OCR では前後に「|」「.」などの余計な文字が付くことがある。
  - 前後に付いた記号 (括弧、「|」「_」「-」「.」など) は無視してよい。

### 5.4 一致した表が複数あるとき

- 一番先にある表 (ページ順、ページ内は上から下、左から右) を読む。
- 他にも一致した表があることを、その番号と一緒に画面に知らせる。

### 5.5 その他の選び方 (補助)

表題で選べないときのために、次の選び方も用意する。

| 方法 | オプション例 | 内容 |
|---|---|---|
| 番号 | `--table 2` | `--list` で表示される通し番号で選ぶ |
| キーワード | `--keyword ボルト` | 表の中か、表のすぐ上 (0.6 インチ以内) にこの文字がある表を選ぶ |
| ページ | `--page 3` | 探すページを絞る。他の方法と組み合わせられる |
| 範囲 | `--roi 100,650,1500,700` | 探す範囲を x,y,幅,高さ (ピクセル) で絞る。他の方法と組み合わせられる |

優先順位は `--table` → `--keyword` → 表題 (既定) とする。

## 6. 処理の流れ

```
TIFF 読み込み (全ページ)
  → [ページごと] 傾き補正
  → 2 値化
  → 罫線の検出 (横線・縦線)
  → 表の検出 (位置・行と列の区切り)
  → 結合セルの判定
  → 表題の読み取り → 対象の表を決める
  → [対象の表のセルごと] 前処理 → OCR → 文字の整形
  → 出力 (TSV / CSV / xlsx / クリップボード)
```

## 7. 画像処理の仕様

以下の数値は試作で動作を確認した値。DPI に合わせて変わる値は式で書く。

### 7.1 2 値化

- 3×3 のガウスぼかしの後、適応的 2 値化 (`ADAPTIVE_THRESH_MEAN_C`、反転、ブロック 31、C=15)。
- 文字と罫線が白 (255)、背景が黒 (0) の画像を作る。

### 7.2 傾き補正

1. 2 値画像から横長の形 (幅 max(20, 画像幅/50)、高さ 1) で横線だけを取り出す。
2. `HoughLinesP` (角度分解能 0.1 度、threshold=100、最小の長さ max(50, 画像幅/8)、隙間 20) で線分を探す。
3. 角度が ±5 度以内の線分の **中央値** を傾きとする。
4. 0.05 度未満なら補正しない。それ以上なら画像の中心で回転し、はみ出た所は白で埋める。

注意: OpenCV の版によって `HoughLinesP` の戻り値の形が `(N,1,4)` と `(N,4)` で違う。`reshape(-1, 4)` で扱うこと。

### 7.3 罫線の検出

| 項目 | 値 |
|---|---|
| 罫線とみなす最小の長さ | max(15, dpi × 0.15) px (300dpi で 45px) |
| 横線の抽出 | 横長の形 (幅 最小の長さ) でオープニング。図面は画像が大きいので、画像幅を基準にしないこと (A0 では長くなりすぎて、短い罫線を取りこぼす) |
| 縦線の抽出 | 縦長の形 (高さ 最小の長さ) でオープニング |
| かすれの補修 | 隙間 max(3, dpi/100) px をクロージングでつなぐ |

**文字の線を罫線と間違えないための工夫 (重要)**

- 縦線の候補のうち、横線に接していないものは捨てる。横線も同様に、縦線に接していないものは捨てる。
- 理由: 文字の縦棒・横棒は罫線から離れているが、本物の罫線は必ず別の向きの罫線とつながっている。
- 実装: 連結成分ごとに、もう一方の向きの線 (少し膨張させたもの) と重なるかを調べる。

### 7.4 表の検出 (図面向け: セルを集めて表にする)

普通の書類のように「罫線のかたまりの外形 = 表」とすると、図面では **図枠と、図枠にくっついた構成表・表題欄が 1 つのかたまりになってしまう**。そこで、先にセル (罫線で囲まれた小さな四角) を見つけ、隣り合うセルを集めて表にする。

1. **セルの候補を探す。** 横線と縦線を合わせた画像で、罫線に囲まれた白い領域 (輪郭の穴) を探す (`findContours` の `RETR_CCOMP` か `RETR_TREE`)。
2. **セルらしいものだけ残す。** 次をすべて満たすものをセルとする。
   - 四角に近い (領域の面積 ÷ 外接する四角の面積 が 0.9 以上)
   - 高さが 2mm 以上 30mm 以下 (dpi から px に直す。1 インチ = 25.4mm)
   - 幅が 2mm 以上、用紙の幅の半分以下
   - これで図枠 (大きすぎる) や、円などの図形 (四角でない) が外れる。
3. **隣り合うセルをまとめる。** 2 つのセルが辺を共有している (辺の位置の差が tol 以内で、辺が重なっている) ならつなげる (Union-Find)。tol = max(3, dpi/60) px。
4. **表にする。** つながったセルのまとまりを 1 つの表とする。
   - セルが 4 個未満、または行か列が 1 つしかないまとまりは表とみなさない (部品の形の四角などを除くため)。
5. **行と列の区切りを求める。** まとまりの中のセルの上下の辺の y 座標を集めて行の区切り、左右の辺の x 座標を集めて列の区切りとする (近い値は 1 つにまとめる)。
6. **くっついた表を分ける。** 構成表と表題欄のように、罫線を共有して 1 つにつながった表は、セルの並びだけでは分けられない。次で分ける。
   - 列の区切りの並びが途中で大きく変わる横線 (その線の上と下で列の区切りの位置がほとんど一致しない) で上下に分ける。
   - 分けたあと、それぞれについて表題 (5 章) を読む。
7. 読む順番 (上から下、左から右) に並べ、通し番号を付ける。番号は全ページ通しとする。

補足:

- 試作 (普通の書類向け) では「罫線のかたまりの外形 = 表」としていた。図面ではこの方法は使えないので、上の方法で作り直すこと。
- 6 の分け方は図面の実物で確認が必要 (15 章の残課題)。

### 7.5 結合セルの判定

7.4 でセルを 1 つずつ見つけているので、結合セルはそのまま分かる。

1. 7.4 の 5 で求めた行と列の区切りで、表を最小のマスに分ける。
2. 見つけたセルごとに、上下左右の辺がどの区切りに当たるかを調べる。
3. セルがまたがるマスの数を、行方向・列方向の広がり (span) とする。左上のマスの位置をセルの位置とする。
4. どのセルにも入らないマスがあれば、空のセルとして扱う (かすれて罫線が切れたときなど)。

確認用の方法 (試作で使った方法。7.4 の結果の点検に使える):

- 隣り合う 2 つのマスの境目に、罫線が **半分以上** 通っているかを調べる (左右の境目は縦線、上下の境目は横線。境目の位置から ±tol px の幅で見る)。
- 半分未満なら同じセル (結合セル) とみなし、Union-Find でまとめる。

## 8. セルの文字の読み取り

### 8.1 前処理 (セルごと)

1. セルの内側を切り出す (罫線を避けるため、四辺を max(2, dpi/150) px 内側に寄せる)。
2. 罫線を消す: 罫線マスクを max(3, dpi/100×2+1) px 膨張させた範囲を白にする。
3. ゴミを消す: 連結成分のうち次のものを捨てる。
   - 面積が max(6, (dpi/300)² × 20) px 未満 (点ゴミ)
   - 切り出し範囲の端に接していて、幅か高さが max(3, dpi/60) px 以下 (罫線のかけら)
4. 文字が残らなければ **空のセル** として扱い、OCR しない。
5. 文字のある範囲だけに切り詰め、文字の部分だけ元の濃淡を使い、それ以外は白にする。
6. 文字の行数を数える (横方向に文字のある行を数える。dpi/30 px 以下の隙間は字の中の隙間とみなして無視)。
7. **1 行の高さが約 50px になるように拡大・縮小する** (倍率は 0.5〜4 倍に制限)。
8. 大津の方法で 2 値化し、周りに 20px の白い余白を付ける。

### 8.2 OCR の設定

| 条件 | 1 回目 | 1 回目が空のとき |
|---|---|---|
| 1 行のセル | `--psm 7` (1 行) | `--psm 13` (生の 1 行) |
| 複数行のセル | `--psm 6` (ブロック) | `--psm 11` (まばらな文字) |

- 言語は既定で `jpn+eng`。
- `--dpi 300` を必ず渡す (付けないと Tesseract が解像度の警告を出す)。
- 速くするため、セルを並列に読む (スレッド)。並列のときは環境変数 `OMP_THREAD_LIMIT=1` にして、Tesseract の中のスレッドを 1 本に絞る。

### 8.3 文字の整形

| 処理 | 例 |
|---|---|
| 日本語の文字の間の空白を消す | `名 古 屋` → `名古屋` |
| 数字の区切りの周りの空白を消す | `1, 200` → `1,200`、`3 . 5` → `3.5` |
| 連続する空白を 1 つにする | `Apple  Pie` → `Apple Pie` |
| 空の行を消す | |
| セル内の改行 | 既定は空白でつなぐ。`--keep-newlines` で改行を残す |

### 8.4 結合セルの出力

- 文字は結合セルの **左上のマス** に入れ、残りのマスは空にする。
- xlsx 出力のときは Excel のセル結合も再現する。

## 9. 外部通信の禁止 (C-1 の実装)

### 9.1 実装

- 起動直後 (引数の解析より前) に、プロセス内の通信機能を封じる関数 `block_network()` を呼ぶ。
- 次の関数を、呼ばれたら例外 (`NetworkBlockedError`) を出す関数に置き換える。
  - `socket.socket.connect` / `connect_ex` / `sendto`
  - `socket.create_connection`
  - `socket.getaddrinfo` / `gethostbyname` / `gethostbyname_ex`
- 起動する外部プログラムは `tesseract` だけにする。クリップボードを使うときは OS 付属のコピー用コマンドも起動してよい (次の 9.2)。

### 9.2 クリップボード

| OS | 方法 |
|---|---|
| Windows | `clip` に **BOM 付き UTF-16** で渡す (UTF-8 だと日本語が化ける) |
| macOS | `pbcopy` に UTF-8 で渡す |
| Linux | `xclip -selection clipboard` か `wl-copy` |

- コピーに失敗したら、エラーで止めずに画面に TSV を表示する。

### 9.3 検証 (テストで確認すること)

1. `block_network()` の後に、接続・名前解決をすると必ず例外になること。
2. ツールを最初から最後まで動かしたとき、Python の監査フック (`sys.addaudithook`) で記録して、
   - `socket.` で始まる出来事が **0 件** であること
   - `subprocess.Popen` で起動したのが **tesseract だけ** であること

## 10. 出力仕様

| 出力先 | 指定 | 文字コードなど |
|---|---|---|
| 画面 | 指定なし | TSV (タブ区切り)。標準出力へ |
| TSV ファイル | `-o result.tsv` | BOM 付き UTF-8、改行 CRLF |
| CSV ファイル | `-o result.csv` | BOM 付き UTF-8、改行 CRLF |
| Excel ファイル | `-o result.xlsx` | 全セルを文字列として保存 (表示形式 `@`)、罫線と折り返し、結合セルを再現 |
| クリップボード | `--clipboard` | TSV。Excel で Ctrl+V するだけで表として貼れる |

- TSV と CSV は、セル内に改行や区切り文字があればダブルクォートで囲む (Python の `csv` モジュールの標準の動き)。
- xlsx を文字列で保存する理由: `001` の先頭の 0 が消えないようにするため。
- 処理の経過や注意は **標準エラー出力** に出す (標準出力の TSV に混ぜない)。

## 11. コマンドライン仕様

```
python -m tableocr 入力.tif [オプション]
```

| オプション | 既定 | 内容 |
|---|---|---|
| `--list` | | 見つかった表の一覧 (番号、ページ、位置、行数×列数、読み取った表題、対象の印) を出して終わる |
| `--title 文字` | `構成表` | 欄外左上の表題にこの文字を含む表を選ぶ |
| `--table N` | | 表を番号で選ぶ |
| `--keyword 文字` | | 表の中か、表のすぐ上にこの文字がある表を選ぶ |
| `--page N` | 全ページ | 探すページ (1 始まり) |
| `--roi x,y,幅,高さ` | | 探す範囲 (ピクセル) |

## 14. 試作で分かったこと (作るときの注意)

| No | 分かったこと | 対応 |
|---|---|---|
| K-01 | `--psm 7` は 2 文字だけのセル (例「好調」) を空で返すことがある | 空なら `--psm 13` で読み直す |
| K-02 | 文字の大きさで精度が大きく変わる。1 行 40/50/60/80px で比べ、50px が一番良かった | 1 行が約 50px になるよう拡大・縮小 |
| K-03 | 適応的 2 値化で、点ゴミが 3×3 の固まりになり、オープニングでは消えない | 連結成分の面積で捨てる |
| K-04 | 傾き補正の後、セルの端に縦線のかけらが残り「\|」と読まれる | 罫線マスクを多めに膨張させて消す。端に接する細い成分も捨てる |
| K-05 | 表全体をまとめて OCR すると罫線が邪魔で文字化けする | 罫線を消してから読む。表題は 1 行だけ切り出して読む |
| K-06 | 表題の前後に余計な記号が付いて読まれることがある (低解像度で「構成表7」など) | 「構成表」を含むかどうかで一致判定 |
| K-07 | `jpn+eng` でも数字を読み間違えることがある (0 と 6、0 と 9 など) | 第一段階では目視確認で補う。改善案は 15 章 |
| K-08 | 日本語の OCR 結果には文字の間に空白が入る | 日本語の文字の間の空白を消す |
| K-09 | `HoughLinesP` の戻り値の形が OpenCV の版で違う | `reshape(-1, 4)` で扱う |
| K-10 | 試作は普通の書類でしか試していない。「罫線のかたまりの外形 = 表」の方法は、図枠があると全部が 1 つの表になる | 図面ではセルを集める方法 (7.4) に変える |

## 15. 残課題

### 15.1 表題の例外表記の確認 (必須)

現状は「構成表」を含むかどうかだけで判定している。実際の図面で次の表記が無いか確認し、必要なら判定を直す。

- 「構成表（続き）」「構成表その2」など、続きや複数の構成表
- 表題が左上以外 (中央、右上、表の中、表の下) にある図面
- 「構成表」以外の言い方 (例: 部品表、部品欄、構成一覧)
- 表題の文字が縦書き、または 90 度回っている図面

### 15.2 図面の実物で確認すること (必須)

- 構成表と表題欄・図枠がくっついているか。くっついているなら、7.4 の 6 の方法で正しく分けられるか。
- 構成表の見出しの行が **上** にあるか **下** にあるか。JIS の部品欄のように、見出しが下で、品番が下から上へ増える書き方の図面があるかもしれない。その場合、Excel に出すときの行の順番を決める必要がある。
- 図面に使われている文字 (CAD の文字) を Tesseract が読めるか。読みにくければ、文字の太さの補正などを考える。
- 図面全体が 90 度回った状態でスキャンされたものがあるか。あれば、Tesseract の向きの判定 (`--psm 0`、`osd` データ。手元で動く) で回転を直す。
- 用紙の大きさと解像度 (A0・400dpi など) で、処理時間とメモリが許容範囲か。厳しければ、表の検出は縮小した画像で行い、文字の読み取りだけ元の解像度で行う。

### 15.3 第二段階以降の候補

- 数字だけの列は、数字だけを読む設定 (`tessedit_char_whitelist`) にして誤りを減らす。
- 複数ページにまたがる構成表、または 1 枚の図面の中で続きになっている構成表を 1 つにつなげる。
- 表を探す前に図面全体を OCR して「構成表」の文字の位置を先に見つけ、そのすぐ下の表を取る方法 (表の候補が多すぎるとき・見つからないときの予備)。
- Excel への貼り付けの自動化。
- 罫線の無い表への対応。
- 読み取りの自信が低いセルに印を付ける (目視確認を楽にする)。

### 15.4 今の制限

- 手書き文字は読めない。
- 結合セルの形が四角でない (L 字など) 場合は、外接する四角として扱う。
- Windows でのクリップボード (`clip` + UTF-16) は試作環境 (Linux) では試せていない。
