# 期限通知フロー 実装手順書

Excel の期限一覧から、Teams へ期限の通知を自動で送る仕組みの作り方。
自分で作るときに、上から順に進めるための手順書。

- 作成日: 2026-11-15
- 状態: 未実装。式は実機で未検証 (6 章のテストで確かめる)
- 人に説明するための資料: [仕様確認資料.pptx](仕様確認資料.pptx)

## 1. 仕組みの概要

- 平日の毎朝 9 時に、クラウド上で自動実行する。パソコンを閉じていても動く。
- 期限一覧から、指定した期限列 (例: 期限3) が 28 日以内の行を拾う。
- Teams のチャネルに、担当者へのメンション付きで一覧表を 1 通投稿する。
- 通知した行には印を付け、同じ期限は二度と通知しない。

## 2. 前提と制約

- 使うのは Power Automate のクラウド版。
- プレミアムコネクタは使わない。使う部品は下のとおりで、すべて標準。

| 部品 | 区分 |
|---|---|
| スケジュール (繰り返し) | 標準 |
| Excel Online (Business) | 標準 |
| Microsoft Teams | 標準 |
| アレイのフィルター処理、選択、作成、HTML テーブルの作成、変数、条件、それぞれに適用 | 標準 (組み込み) |

- Excel ファイルは `.xlsx` で、会社用の OneDrive か SharePoint に置く。
- フローは作った人のアカウントで動く。その人が異動や退職をすると止まる。
- 画面の版によって、アクションや設定の表示名が少し違う場合がある。

## 3. Excel の準備

### 3.1 期限一覧 (テーブル名「期限一覧」)

- [ ] 表の範囲を選び、`Ctrl + T` でテーブルにする。
- [ ] テーブル名を「期限一覧」にする。
- [ ] 下の「追加」の列を 3 つ足す。

| 列名 | 区分 | 内容 | 入力する人 |
|---|---|---|---|
| 車種コード | 既存 | 同じコードが複数行にあってよい | 人 |
| 開発フェーズ | 既存 | | 人 |
| 期限1 〜 期限6 | 既存 | 値は日付。1 から順に工程順 | 人 |
| 番号 | 追加 | 行ごとに重複しない番号。数式 `=ROW()` でもよい | 人または数式 |
| 担当者 | 追加 | 名簿にある名前。複数は `;` か `、` で区切る | 人 |
| 通知済み | 追加 | 通知した期限の記録。例: `期限3(11/16);` | フローが自動で記入 |

- 追加した列は非表示にしてもよい。フローは問題なく読み書きできる。
- 期限の列名は、別の列名を含まない名前にする。「期限1」と「期限10」が両方あると誤判定する。

### 3.2 名簿 (テーブル名「名簿」)

- [ ] 別シートに表を作り、テーブルにする。
- [ ] テーブル名を「名簿」にする。

| 列名 | 内容 |
|---|---|
| 名前 | 期限一覧の担当者欄に書く名前と、完全に同じ表記。重複不可 |
| メールアドレス | Teams で使っているアドレス |

- 同姓がいる場合は「田中(太)」のように区別する。

## 4. フローの作成

Power Automate の「作成」から「スケジュール済みクラウドフロー」を選ぶ。

各アクションの名前は、「」内のとおりに変える。式がその名前を参照するため。
名前に空白は入れない。

### 手順 1. トリガー (実行の合図)

- [ ] 間隔は「1 週間」。曜日は月〜金。時刻は 9 時。
- [ ] タイムゾーンは「(UTC+09:00) 大阪、札幌、東京」。

### 手順 2. 設定値を置く

- [ ] 「変数を初期化する」を 3 つ追加する。

| 名前 | 種類 | 値 |
|---|---|---|
| 対象期限 | 文字列 | `期限3` |
| 通知日数 | 整数 | `28` |
| メンション | 文字列 | 空のまま |

### 手順 3. Excel を読む

- [ ] 「表内に存在する行を一覧表示」を 2 つ追加する。
- [ ] 1 つ目の名前を「期限一覧を取得」にする。
  - テーブルは「期限一覧」。
  - 日付時刻の形式を「ISO 8601」にする。これを忘れると日付が数値になり、比較できない。
  - 行が 256 を超えるなら、設定で「改ページ」をオンにする。
- [ ] 2 つ目の名前を「名簿を取得」にする。
  - テーブルは「名簿」。

### 手順 4. 通知する行だけ残す

- [ ] 「アレイのフィルター処理」を追加。名前「通知対象」。
- [ ] 差出人に「期限一覧を取得」の `value` を入れる。
- [ ] 「詳細設定モードで編集」に切り替え、次を貼る。

```
@and(
  not(empty(item()?[variables('対象期限')])),
  not(contains(coalesce(item()?['通知済み'], ''), variables('対象期限'))),
  lessOrEquals(
    coalesce(item()?[variables('対象期限')], '9999'),
    convertTimeZone(addDays(utcNow(), variables('通知日数')), 'UTC', 'Tokyo Standard Time', 'yyyy-MM-ddT23:59:59')
  )
)
```

式の意味 (上から順に)

- 対象の期限列が空でない。
- 「通知済み」に、対象の期限の記録がまだない。
- 対象の期限が、今日 (日本時間) から通知日数以内。期限切れも含む。

### 手順 5. 0 件なら終わり

- [ ] 「条件」を追加。左に次の式、「次の値より大きい」、右に `0`。
- 手順 6 〜 10 は、すべて「はいの場合」の中に置く。

```
length(body('通知対象'))
```

### 手順 6. 担当者の名前を 1 人ずつに分ける

- [ ] 「選択」を追加。名前「担当者だけ選択」。
  - 差出人は「通知対象」の出力。
  - マップを文字入力モードに切り替え、次の式を入れる。

```
item()?['担当者']
```

- [ ] 「作成」を追加。名前「担当者を分割」。次の式を入れる。
  - 全角の `；` と `、` を `;` にそろえ、空白を消してから分ける式。

```
split(replace(replace(replace(replace(join(body('担当者だけ選択'), ';'), '；', ';'), '、', ';'), ' ', ''), '　', ''), ';')
```

- [ ] 「アレイのフィルター処理」を追加。名前「担当者リスト」。
  - 差出人に次の式を入れる (重複を除く)。

```
union(outputs('担当者を分割'), outputs('担当者を分割'))
```

  - 詳細設定モードに次の式を入れる (空欄を除く)。

```
@not(equals(item(), ''))
```

### 手順 7. 名簿を引いてメンションを作る

- [ ] 「それぞれに適用」を追加。名前「担当者ループ」。対象は「担当者リスト」の出力。
- ループの中に、次の順で置く。

**7-1. 名簿から探す**

- [ ] 「アレイのフィルター処理」を追加。名前「名簿から探す」。
- [ ] 差出人に「名簿を取得」の `value` を入れる。
- [ ] 詳細設定モードに次の式を入れる。

```
@equals(item()?['名前'], items('担当者ループ'))
```

**7-2. 見つかったかどうかで分ける**

- [ ] 「条件」を追加。左に次の式、「次の値より大きい」、右に `0`。

```
length(body('名簿から探す'))
```

**7-3. はいの場合 (名簿に名前がある)**

- [ ] Teams の「ユーザーの @mention トークンを取得する」を追加。ユーザー欄に次の式。

```
first(body('名簿から探す'))?['メールアドレス']
```

- [ ] 「文字列変数に追加」を追加。対象は「メンション」。値はトークンの出力と半角スペース。

**7-4. いいえの場合 (名簿に名前がない)**

- [ ] 「文字列変数に追加」を追加。対象は「メンション」。値は「現在のアイテム」と `(名簿なし) `。

### 手順 8. 一覧表を作る

- [ ] 「選択」を追加。名前「表の中身」。差出人は「通知対象」の出力。
- [ ] マップに次の 4 列を作る。

| 左 (見出し) | 右 (値の式) |
|---|---|
| 車種コード | `item()?['車種コード']` |
| 開発フェーズ | `item()?['開発フェーズ']` |
| 期限 | `formatDateTime(item()?[variables('対象期限')], 'yyyy/MM/dd')` |
| 担当者 | `item()?['担当者']` |

- [ ] 「HTML テーブルの作成」を追加。差出人は「表の中身」の出力。

### 手順 9. Teams に投稿

- [ ] 「チャットまたはチャネルでメッセージを投稿する」を追加。
- [ ] 投稿者は「フロー ボット」。投稿先は通知したいチャネル。
- [ ] 本文を次の順に並べる。
  1. 変数「メンション」
  2. 改行
  3. 変数「対象期限」+「が」+ 変数「通知日数」+「日以内の案件です。」
  4. 改行
  5. 「HTML テーブルの作成」の出力

### 手順 10. 通知済みの印を付ける

- [ ] 「それぞれに適用」を追加。名前「通知済みを記録」。対象は「通知対象」の出力。
- [ ] 中に Excel の「行の更新」を置く。
  - テーブルは「期限一覧」。
  - キー列は「番号」。
  - キー値に次の式を入れる。

```
items('通知済みを記録')?['番号']
```

  - 「通知済み」の欄に次の式を入れる。他の欄は空のままにする (空の欄は書き換えられない)。

```
concat(coalesce(items('通知済みを記録')?['通知済み'], ''), variables('対象期限'), '(', convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time', 'M/d'), ');')
```

## 5. フローの形 (完成図)

```
繰り返し (月〜金 9:00)
├ 変数: 対象期限 / 通知日数 / メンション
├ 期限一覧を取得
├ 名簿を取得
├ 通知対象 (絞り込み)
└ 条件: 通知対象が 1 件以上
   └ はい
      ├ 担当者だけ選択
      ├ 担当者を分割
      ├ 担当者リスト
      ├ 担当者ループ
      │  ├ 名簿から探す
      │  └ 条件: 見つかった
      │     ├ はい: メンションのトークンを取得 → メンションに追加
      │     └ いいえ: 名前と「(名簿なし)」をメンションに追加
      ├ 表の中身
      ├ HTML テーブルの作成
      ├ Teams に投稿
      └ 通知済みを記録
         └ 行の更新
```

## 6. テスト

テスト用の Excel で行う。対象期限は `期限3`、通知日数は `28` とする。

### 6.1 テスト用の行

| 行 | 期限3 の値 | 担当者 | 期待する結果 |
|---|---|---|---|
| 1 | 今日 | 1 人 | 載る |
| 2 | 27 日後 | 2 人 (`;` 区切り) | 載る。2 人ともメンション |
| 3 | 期限切れ | 2 人 (`、` 区切り) | 載る |
| 4 | 27 日後 | 名簿にない名前 | 載る。「(名簿なし)」と表示 |
| 5 | 30 日後 | 1 人 | 載らない |
| 6 | 空 | 1 人 | 載らない |
| 7 | 27 日後。行 1 と同じ車種コード | 1 人 | 載る。行 1 とは別の行として |

### 6.2 確認の手順

- [ ] 「テスト」から手動で実行する。
- [ ] 行 1、2、3、4、7 だけが投稿される。
- [ ] 同じ人が複数の行にいても、メンションは 1 回だけ。
- [ ] その 5 行の「通知済み」に `期限3(今日の日付);` が入る。
- [ ] 行 5、6 の「通知済み」は空のまま。
- [ ] もう一度実行し、何も投稿されない。
- [ ] 行 5 の期限3 を 27 日後に直して実行し、行 5 だけが投稿される。

## 7. 運用

### 7.1 設定の変え方

| やりたいこと | 直す場所 |
|---|---|
| 通知する期限を変える | 手順 2 の「対象期限」の値 |
| 何日前に通知するかを変える | 手順 2 の「通知日数」の値 |
| 担当者を足す | 名簿シートに行を足す |
| 同じ期限をもう一度通知する | その行の「通知済み」から該当の記録を消す |

### 7.2 通知する期限を複数にする場合

- フローを複製し、「対象期限」の値だけ変える (例: `期限5`)。
- 実行時刻を 10 分ずらす (例: 9:00 と 9:10)。同時に動くと、印の書き込みがぶつかるため。
- 通知日数はフローごとに変えられる。

### 7.3 動きの補足

- 土日に 28 日前を迎えた行は、月曜の朝に載る。
- 平日の祝日も実行する。
- 投稿に失敗した日は印が付かず、翌朝にもう一度試される。
- 初回実行では、すでに 28 日以内や期限切れの行が、まとめて 1 回通知される。
- 完了かどうかは判定しない。期限が近づいた行は、必ず 1 回通知される。

## 8. 困ったとき

| 症状 | 考えられる原因 | 対処 |
|---|---|---|
| 何も投稿されない | 対象の行がない | 手順 4 の出力を実行履歴で確認する |
| 何も投稿されない | 日付の形式が ISO 8601 になっていない | 手順 3 の設定を確認する |
| 手順 7 で失敗する | 名簿のアドレスが間違っている | 名簿を直す。直すまで毎朝止まる |
| 同じ行が毎日通知される | 「番号」が空、または重複している | 「番号」を直す |
| 式でエラーになる | アクション名や列名が式と違う | 名前を「」内のとおりに直す |
| 期限を変えたのに通知されない | 「通知済み」に記録が残っている | 該当の記録を消す |

## 9. 未決のこと

仕様確認資料で確認してもらう点。決まったらこの手順書に反映する。

- 通知は 1 回だけでよいか。期限直前の再通知は要るか。
- 通知する期限はどれか。何日前に通知するか。
- 投稿先のチャネルはどこにするか。
- 担当者欄と名簿は、誰が入力し更新するか。
- 期限を変更したときの再通知は、手作業でよいか。
- 完了した案件を通知から外す必要はあるか。
- 祝日の通知を止める必要はあるか。
- フローの持ち主 (作成者) を誰にするか。
