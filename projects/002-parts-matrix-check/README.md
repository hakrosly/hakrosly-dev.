## 概要

システムに登録されている部品表と、事務所で作っている品番マトリックス (Excel) の中身が合っているかを、Excel VBA で確かめる。
今は紙に出して赤ペンで確かめている作業を、Excel に置き換える。

- 部品表は形が一律。マトリックスは設計者や部品の種類によって形がばらばらで、セルの結合もある。
- 両方を「品番 × 仕様」の縦長の一覧 (共通の形) に直してから比べる。
- マトリックスの形は、人が最初に 1 回だけマウスで教える (品番の範囲、名称の範囲、仕様の見出しの範囲)。ツールが覚えて、次からは使い回す。
- 結果は Excel のブック 1 つにまとまる。食い違いの一覧だけでなく、「本当にチェックできたか」が分かる証拠 (色を付けた写し、消し込み、検算、抜き打ち) も入る。
- 元のファイルは書き換えない。外部通信は一切しない。

## 会社での始め方

1. このフォルダをまるごと持ち込む (GitHub の「Download ZIP」など)。
2. `handover/照合ツール_ひな形.xlsx` を開き、シート「はじめに」の手順どおりに進める。
3. うまくいかない所は、`spec.md` の 14 章の順番で Copilot に頼む。

Copilot には、`spec.md` と、直したいモジュール (`vba/` の中の 1 本) を渡す。フォルダ全体は渡さない。

## 作る側の確かめ方 (devtools)

LibreOffice と Python が入っている環境で使う。会社の PC では不要。

```bash
cd devtools
python3 lint_vba.py    # 書き間違いと、禁止された言葉の点検
python3 run_tests.py   # LibreOffice でコードを動かし、自己診断を実行
python3 build.py       # vba_import/ と handover/ のファイルを作り直す
```

- `vba/` を直したら、`build.py` を実行して `vba_import/` と `handover/` を作り直す。
- `lo_shim/` は、LibreOffice で動かすときだけ使う代わりの部品 (Linux には `Scripting.Dictionary` が無いため)。Excel では使わない。
