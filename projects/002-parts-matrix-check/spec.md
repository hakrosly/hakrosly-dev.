- 7 章の「チェックできているかを確かめる仕組み」は弱めないこと。警告や検算を消して「合った」ように見せる直し方は禁止。

## 1. 目的

**部品表** と **品番マトリックス** の中身が合っているかを、Excel の上で自動で確かめる。

今は、両方の表を紙に出して、赤ペンで 1 つずつ印を付けて確かめている。これを Excel に置き換える。
置き換えるからには、**「本当に全部チェックできたか」が後から分かること** を、食い違いを見つけることと同じ重さで扱う。

| 言葉 | 意味 |
|---|---|
| 部品表 | システムに登録されている部品の一覧。部品名称、品番、使われている車の仕様などが入っている。**形は一律** |
| 品番マトリックス (以下、マトリックス) | 事務所で使いやすいように作った Excel の表。片方の軸に品番、もう片方の軸に車の仕様が並ぶ。**形は設計者や部品の種類によってばらばら**。セルの結合もある |
| 仕様 | 車の作り分けの単位 (グレード、駆動方式など)。部品がどの車に使われるかを表す |
| 照合 | 2 つの表を突き合わせて、食い違いを探すこと |
| 消し込み | 突き合わせた項目に、1 つずつ印を付けていくこと (赤ペンの印と同じ) |

- 入力: 部品表のファイル 1 つと、マトリックスのファイル 1 つ (1 シート)。
- 出力: **結果のブック 1 つ (Excel)**。食い違いの一覧、色を付けたマトリックスの写し、消し込み、検算などが、シートに分かれて入る (8 章)。
- 使う人: マトリックスを作る設計者、または確認する人。

## 2. 絶対条件

| No | 条件 | 内容 |
|---|---|---|
| C-1 | **外部通信の禁止** | 実行中は一切の外部通信をしない。クラウドのサービス、Web API、テレメトリ、自動更新、オンラインのデータ取得はすべて禁止 |
| C-2 | **ローカル完結** | 入力の読み込みから出力まで、すべて手元の PC の中で完結させる |
| C-3 | オフラインで導入できること | インターネットにつながらない PC へ導入する手順を README に書く (部品を持ち込んで入れる手順) |
| C-4 | 社内データを入れない | 本物の部品表やマトリックスはリポジトリに入れない。テストには自分で作ったデータを使う |
| C-5 | 言語 | 画面の表示、エラー、説明は日本語。専門用語には短い説明を添える |
| C-6 | **元のファイルを書き換えない** | 部品表とマトリックスは読み取り専用で開く。保存もしない。色は結果のブックの中の写しに付ける |
| C-7 | **追加の部品を入れない** | Excel に最初から入っている VBA の機能だけで作る。追加のソフト、アドイン、参照設定の追加は使わない |
| C-8 | **黙って捨てない** | 読めなかったセル、対象から外した行や列は、必ず結果に出す。「何も出ない = 合っている」と言える状態を保つ |
| C-9 | **証拠を残す** | 照合のたびに、何を・どの設定で・どこまで見たかを、結果のブックに残す (7 章) |

C-1 を VBA で守るための決まり:

- 使ってはいけないもの: `WinHttp`、`MSXML2.XMLHTTP`、`InternetExplorer`、Web クエリ、`Shell` による外部プログラムの起動、Windows API の `Declare`。
- ファイルを開くときは `UpdateLinks:=0` を付ける (他のファイルへのリンクを更新させない)。
- 開く相手のファイルに入っているマクロは動かさない (`modFile.OpenReadOnly`)。
- 今のコードに上の言葉が無いことは、点検の道具 (`devtools/lint_vba.py`) で確かめてある。

## 4. 入力仕様

### 4.1 部品表

- システムから出した一覧。形は一律。
- 見出しの行が 1 行あり、その下に 1 行ずつ部品のデータが並ぶ。
- 列の名前と並びは **未確認** (13.1 の Q-01、Q-02)。そのため列の場所は、コードに書かず設定シートに持たせてある (6.2)。
- 仕様の持ち方は、次の 3 つのどれかと想定する。今のコードは (a) と (c) に対応している。

| 型 | 仕様の持ち方 | 例 |
|---|---|---|
| (a) 縦持ち | 1 行が「品番 1 つ × 仕様 1 つ」 | 同じ品番の行が、仕様の数だけ並ぶ |
| (b) 横持ち | 仕様ごとに列があり、印や員数が入る | 部品表そのものがマトリックスの形 |
| (c) まとめ書き | 1 つのセルに仕様が複数入る | `S1,S2,S3` |

(b) だった場合は、部品表もマトリックスと同じ読み方で読むように直す (13.2 の S-6)。

### 4.2 マトリックス

決まった形は無い。ただし次のことは共通と想定する。

- Excel の表である。
- 片方の軸に品番、もう片方の軸に車の仕様が並ぶ。
- 品番と仕様が交わるセルに、使うかどうかの印 (○ など) か、員数 (使う個数) が入る。

形の違いとして想定するものと、今のコードの対応:

| No | 違い | 例 | 対応 |
|---|---|---|---|
| F-1 | 品番の向き | 品番が縦に並ぶ表と、横に並ぶ表がある | 済 |
| F-2 | 表の始まる場所 | 上に題名や日付の行があり、表は途中から始まる | 済 (範囲で教える) |
| F-3 | 仕様の見出しが何段もある | 上の段がグレード、下の段が駆動方式、など | 済 |
| F-4 | 見出しのセル結合 | 上の段の「STD」が、下の段の 2 列分にまたがって結合されている | 済 |
| F-5 | 見出しの空欄 | 結合せずに、左と同じ値のセルを空欄にしている | 済 (設定で切り替え) |
| F-6 | 値のセル結合 | ○ が 1 つ、複数の仕様の列にまたがって結合されている | 済 |
| F-7 | 途中の区切り | 品番の並びの途中に、空行や小見出しの行がある | 済 (品番が空の行は飛ばす) |
| F-8 | 関係ない列 | 備考、材質、図番など、仕様ではない列が混ざる | 済 (仕様対応表で「対象外」) |
| F-9 | 品番の書き方 | 全角と半角、ハイフンの有無、前後の空白、1 つのセルに改行で 2 つ | 済 |
| F-10 | 印の種類 | ○、●、◎、レ、数字、－、× など | 済 (一覧を設定で持つ) |
| F-11 | 見た目で意味を表す | 取り消し線、塗りつぶし、非表示の行や列 | 取り消し線と非表示は警告する。色の意味は読まない |
| F-12 | セルに品番そのものを書く | 「名称 × 仕様」の表で、交わるセルに品番を書く | **未対応** (13.2 の S-4) |

形の例 (同じ中身を 2 通りに書いたもの):

```
例 1: 品番が縦。見出しが 2 段で、上の段が結合されている

         |            |    STD    |    DX     |
  名称   |  品番      | 2WD | 4WD | 2WD | 4WD |
  -------+------------+-----+-----+-----+-----+
  部品A  | AB123-0010 |  ○  |  ○  |     |     |
  部品B  | AB123-0020 |     |     |  ○  |  ○  |

例 2: 品番が横。仕様が縦

               | 部品A      | 部品B      |
               | AB123-0010 | AB123-0020 |
  -----+-------+------------+------------+
  STD  | 2WD   |     ○      |            |
       | 4WD   |     ○      |            |
  DX   | 2WD   |            |     ○      |
       | 4WD   |            |     ○      |
```

## 5. 考え方と処理の流れ

### 5.1 基本の考え方

| No | 考え方 | 理由 |
|---|---|---|
| P-1 | **両方を同じ形 (共通の形) に直してから比べる** | 形の違いを読み取りの所だけに閉じ込める。比べる処理は 1 つで済む |
| P-2 | **マトリックスの形は人が教え、ツールが覚える** | 形がばらばらなので、自動で当てると読み違える。確認用のツールが読み違えると「合っている」と誤って伝えてしまう |
| P-3 | **教えるのは 3 か所だけ** | 品番の範囲、名称の範囲、仕様の見出しの範囲。マウスで選ぶ。値のセルの場所は、この 3 つから自動で決まる |
| P-4 | **読み取った結果を必ず見せる** | 共通の形に直したものをシートに書き出す。人が「正しく読めたか」を確かめられる |
| P-5 | **段階の間はシートで受け渡す** | 読み取り、照合、結果の各段階を別々に直して確かめられる |
| P-6 | **両方の全部に印を付ける (消し込み)** | 食い違いだけを出すのではなく、見たもの全部に「一致 / 不一致 / 判断できない / 対象外」を付ける。印の無いものが残らないことで、もれが無いと分かる |
| P-7 | **ツール自身を疑う** | 数の検算、わざと間違いを入れる抜き打ち、自己診断を、仕組みとして持つ (7 章) |

共通の形とは、「1 行 = 品番 1 つ × 仕様 1 つ」の縦長の一覧のこと。

### 5.2 不動の部分と、会社で合わせる部分

| 区分 | 中身 | どこで合わせるか |
|---|---|---|
| **不動 (作成済み)** | 文字のそろえ方、結合セルのほどき方、縦横の扱い、共通の形、照合、消し込み、検算、抜き打ち、結果のブック、自己診断 | 直さない (直すなら自己診断を通す) |
| **設定で合わせる** | 部品表の列の名前、絞り込み、マトリックスの範囲、印の一覧、仕様の呼び名の対応 | ツール用ブックの設定シート (コードは直さない) |
| **コードを直して合わせる** | 部品表が想定と違う形だった場合 (`modBom`)。マトリックスが 4.2 の F-12 のような別の種類だった場合 (`modMatrix`)。画面の使い勝手 (`modMain`) | Copilot で、該当モジュールだけ |

### 5.3 処理の流れ

```
① 部品表を読む                     [modBom]
     部品表のファイル → 設定_部品表 に従って読む → シート「読取_部品表」

② マトリックスを読む               [modMatrix]
     初めての形なら、マウスで 3 か所を教える → シート「設定_マトリックス」に保存
     マトリックスのファイル → 設定に従って読む (結合セルをほどく) → シート「読取_マトリックス」
     見出しの文字を → シート「仕様対応表」に足す (うめられる所は自動でうめる)

③ 照合する                         [modCompare, modReport]
     仕様対応表に未設定があれば、ここで止まって知らせる
     読取_部品表 と 読取_マトリックス を比べる
     → 検算と抜き打ち
     → 結果のブック (新しい Excel ブック) を作り、「照合結果」フォルダに保存
```

読み取りの途中で気付いたこと (警告) は、シート「読取_警告」にたまり、結果のブックに必ず出る。
2 回目からは、形を教える作業と対応表を書く作業がほぼ不要になる。設定と対応表を覚えているため。

## 6. 処理の詳しい仕様

### 6.1 文字のそろえ方 (`modText`)

比べる前に、両方の文字へ同じ処理をかける。元の文字は別に残し、画面や結果には元の文字を出す。

品番にかける処理 (この順番で行う):

1. セルの中の改行を取る (1 セルに複数の品番を許す設定のときは、改行で分けてから以下を行う)。
2. 全角の英数字と記号を半角にする (`StrConv(s, vbNarrow, 1041)`)。
3. 英字を大文字にする。
4. 半角と全角の空白をすべて取る。
5. 「ハイフンとみなす文字」を半角の `-` に置き換える。
6. 設定「ハイフンを無視する」が「する」なら、`-` をすべて取る (既定は「しない」)。

名称と仕様の文字にかける処理: 1〜4 だけを行う (名称の長音「ー」を壊さないため)。

値のセル (印) にかける処理: 1〜5 を行ってから、印の一覧と比べる。

決まり:

- 「ハイフンとみなす文字」「あり を表す印」「なし を表す印」は、**シート「設定_文字」に 1 行 1 文字で置く**。
  - 理由: VBA の編集画面は、一部の記号 (✓ など) を表示も保存もできない。
- コードに記号を書くときは、`ChrW(&H25CB)` のように番号で書く (初期値は `modText.DefaultTextRows`)。
- 品番のセルが文字でなかったとき (数値や日付。先頭の 0 が消えた、桁が丸められた、などのおそれ) は、表示されている文字 (`.Text`) を使い、警告 W-4 を出す。
- 品番のセルがエラー値 (`#N/A` など) のときは読まずに、警告 W-4 を出す。

### 6.2 部品表の読み取り (`modBom`)

設定はシート「設定_部品表」に持つ。列は見出しの文字で指定する (列の並びが変わっても動くように)。

| 設定の項目 | 例 | 説明 |
|---|---|---|
| シート名 | (空) | 空なら 1 枚目のシート |
| 見出しの行 | 1 | 見出しがある行の番号 |
| 品番の列 | 品番 | 見出しの文字 |
| 名称の列 | 部品名称 | 見出しの文字。空なら名称は比べない |
| 仕様の列 | 仕様コード | 見出しの文字。複数あるときはカンマで並べる。値を ` / ` でつないで 1 つの仕様コードにする |
| 仕様の区切り文字 | , | 1 セルに仕様が複数入るとき (4.1 の (c))。空なら分けない |
| 員数の列 | 員数 | 空なら員数は比べない |
| 絞り込みの列 | 品番 | 空可。そのマトリックスが扱う部品だけに絞るための列 |
| 絞り込みの値 | AB123* | `Like` の書き方。この形に合う行だけを「範囲の中」とする |

手順:

1. 使われている範囲の値を、まとめて配列に読む。
2. 見出しの行から、各設定の列を探す (全角と半角、空白の違いは無視)。見つからなければ、その名前を知らせて止まる。
3. 1 行ずつ、品番・名称・仕様・員数を取り出し、6.1 の処理をかける。品番が空の行は飛ばし、数を数える。
4. 同じ「品番 × 仕様」が 2 行以上あれば、警告 W-7 を出す。
5. 検算のために、品番の列の空でないセルの数を、Excel の関数 (`COUNTA`) で別に数えておく。
6. シート「読取_部品表」に書き出す (10.2)。

### 6.3 マトリックスの読み取り設定 (`modMatrix`)

設定はシート「設定_マトリックス」に、**1 つの表につき 1 行** で持つ。

| 設定の項目 | 例 | 説明 |
|---|---|---|
| 設定名 | ブラケット前側 | 利用者が付ける名前。次回はこの名前で呼び出す |
| シート名 | Sheet1 | 対象のシート |
| 品番の向き | 縦 | 縦 = 品番が上から下へ並ぶ。横 = 左から右へ並ぶ |
| 品番の範囲 | C6:C40 | 品番が並ぶセル。見出しは含めない |
| 名称の範囲 | B6:B40 | 空可。品番の範囲と同じ長さ |
| 仕様の見出しの範囲 | E3:P5 | 仕様の見出し。何段あってもよい |
| 値の種類 | 印 | 印 = 使う/使わない。員数 = 個数 |
| 見出しの空欄の引き継ぎ | する | F-5 への対応 (6.4) |
| 1 セルに複数の品番 | 分けない | 「分ける」なら改行で分ける |
| 品番の形 | (空) | 空可。`Like` の書き方。合わないセルは品番として読まず、警告 W-9 を出す |

範囲の決まり (品番の向きが「縦」のとき。`CheckLayout` が確かめる):

- 品番の範囲は「n 行 × 1 列以上」。2 列以上のときは、左から順につないで 1 つの品番にする。
- 仕様の見出しの範囲は「k 行 × m 列」。この m 列が仕様の列になる。
- **値のセルは「品番の範囲の行」と「見出しの範囲の列」が交わる所**。別に指定しない。
- 見出しの範囲の行は、品番の範囲の行と重なってはいけない。列も重なってはいけない。
- 名称の範囲は、品番の範囲と同じ行に並ぶこと。

品番の向きが「横」のときは、上の「行」と「列」を入れ替えて読む。
コードの中では、品番が並ぶ向きを `p`、仕様が並ぶ向きを `s` と呼び、縦横の違いを小さな関数 (`GV`、`GRaw`、`GCell`) だけに閉じ込めてある。

1 枚のシートに表が 2 つ以上あるときは、表ごとに設定を 1 行ずつ作る。

### 6.4 結合セルと空欄の扱い (`modMatrix`)

結合されたセルは、Excel の中では **左上のセルだけに値があり、残りは空** になっている。次のように扱う。

| 場所 | 扱い |
|---|---|
| 見出し (F-4) | 結合されていれば、結合範囲の左上の値を、範囲の全部のセルの値とみなす |
| 名称 | 同じ。縦に結合された名称は、その範囲の全部の品番の名称とみなす |
| 品番 | 結合されていれば、**結合範囲で 1 つの品番** として読む。値のセルは、その範囲の行すべてを見る (あり > 判断できない > なし の順で強い方を採る) |
| 値 (F-6) | 結合されていれば、結合範囲の左上の値を、**範囲にかかる全部の「品番 × 仕様」に当てはめる** |

速さのための工夫: 値は配列でまとめて読み、**空のセルだけ** を 1 つずつ調べて結合かどうかを見る (結合の残りのセルは必ず空だから)。

見出しの空欄の引き継ぎ (F-5。設定が「する」のときだけ):

- 対象は、**一番下の段以外** の見出しのセル。
- セルが空で、結合もされていないとき、左隣の列の値を引き継ぐ。
- ただし引き継ぐのは、**一つ上の段の値が左隣と同じ間だけ**。
- 品番の向きが「横」のときは、「左」を「上」に読み替える。

列ごとの「見出しの文字」の作り方:

1. その列の見出しのセルを、上の段から順に取る (結合と引き継ぎを反映した値)。
2. 空の段は飛ばす。上の段と同じ文字が続くときは 1 つにする。
3. 残った文字を ` / ` でつなぐ。例: `STD / 2WD`
4. 全部の段が空の列は読まない。警告 W-6 を出す。

### 6.5 マトリックスの読み取り手順 (`modMatrix.ReadMatrixSheet`)

1. 設定の範囲が決まりに合っているかを確かめる。合わなければ、理由を知らせて止まる。
2. 仕様の列ごとに「見出しの文字」を作る (6.4)。非表示の列なら、読んだうえで警告 W-5 を出す。
3. 品番の範囲を先頭から順に読む。
   - 品番のセルが空なら、その行は飛ばす (F-7)。飛ばした数を数える。
   - 「品番の形」が設定されていて、品番キーが合わなければ、読まずに警告 W-9 を出す。
   - 同じ品番が 2 回以上出たら、警告 W-1 を出す (照合では、どちらかで「あり」なら「あり」として扱う)。
   - 行が非表示なら、読んだうえで警告 W-5 を出す。
   - 品番の文字に取り消し線があれば、読んだうえで警告 W-8 を出す (文字の一部だけの取り消し線も同じ)。
4. 品番ごとに、仕様の列のセルを読み、次のように判定する。

| 値の種類 | セルの値 | 判定 |
|---|---|---|
| 印・員数 | 空、または「なし を表す印」 | なし |
| 印・員数 | 「あり を表す印」 | あり (員数は不明) |
| 員数 | 0 より大きい数 | あり (員数 = その数) |
| 員数 | 0 | なし |
| 印・員数 | それ以外 (エラー値も含む) | 判断できない。警告 W-3 |

5. シート「読取_マトリックス」に、**値のセル 1 つにつき 1 行** を書く (品番 × 仕様の列。「なし」も書く)。
   - 「なし」も書くのは、消し込みのため (全部のセルに状態を付ける)。
6. 検算のために、**読み取りとは別の道筋で印を数える** (7.2 の K-3)。
   - 品番の範囲 × 見出しの範囲 の全部のセルを端から見て、「あり」の印が入ったセルを数える。
   - 読み取りで使った「あり」のセルの数と比べる。合わなければ、読まれていない印がある (その場所も記録する)。
7. 品番の範囲のすぐ先のセルが空でなければ、警告 W-11 を出す (行が増えたかもしれない)。
8. 見出しの文字を、全部「仕様対応表」に足す (その設定名でまだ無いものだけ)。

### 6.6 マトリックスの形を教える画面 (`modMain.TeachLayout`)

`Application.InputBox` の範囲を選ぶ機能 (`Type:=8`) を使う。専用の画面 (フォーム) は第一段階では作らない。

1. 「品番が並んでいるセルを選んでください (見出しは含めない)」
2. 「部品名称が並んでいるセルを選んでください (無ければキャンセル)」
3. 「仕様の見出しのセルを選んでください (何段あっても全部)」
4. 品番の向きは、1 で選んだ範囲が縦長か横長かで決める。1 行 1 列のときだけ利用者に聞く。
5. 値の種類 (印 / 員数) を聞く。
6. 範囲の決まり (6.3) を確かめてから、「設定_マトリックス」に保存する。

引き継ぎ・複数の品番・品番の形は、保存した後でシート「設定_マトリックス」を直接書き換える。

### 6.7 仕様対応表 (`modSpecMap`)

マトリックスの見出しの文字と、部品表の仕様コードは、呼び名が違うことがある。対応をシート「仕様対応表」に持つ。

| 列 | 例 | 説明 |
|---|---|---|
| 設定名 | ブラケット前側 | どのマトリックスの設定か |
| 見出しの文字 | STD / 2WD | 6.4 で作った文字 |
| 仕様コード | S1 | 部品表の側の呼び名。空欄は「未設定」 |
| 対象外 | (空欄) | 「対象外」と書くと、その列は比べない (備考の列など。F-8) |
| メモ | | 自動でうめた行には「自動でうめた」と入る |

決まり:

- 1 つの見出しが複数の仕様コードに当たるときは、**行を複数書く**。
- 自動でうめる: 見出しの文字と仕様コードが、6.1 の処理をかけた後で同じなら、その仕様コードを入れる。
- **未設定の見出しが 1 つでも残っていたら、照合を始めない**。未設定の一覧を見せる。
  - 理由: 黙って飛ばすと、比べていない列があるのに「合っている」と見えてしまう (C-8)。
- 複数の見出しが同じ仕様コードに当たっているとき、同じ見出しの文字の列が複数あるときは、警告 W-2 を出す (どれかで「あり」なら「あり」として扱う)。
- 対象外にした見出しは、結果のまとめに一覧で出す。

### 6.8 照合 (`modCompare.CompareCore`)

入力は配列だけで、シートやファイルには触らない。同じ入力なら必ず同じ結果になる。

準備:

- B = 部品表の「品番 × 仕様コード」の集まり。
- M = マトリックスの「あり」の「品番 × 仕様コード」の集まり (見出しを仕様対応表で仕様コードに直したもの)。
- T = 対象の仕様 = 仕様対応表でマトリックスの見出しに対応づけた仕様コードの全部。
- 部品表の「T に入らない仕様」は比べない。その一覧をまとめに出す。

食い違いの種類 (不一致):

| 記号 | 名前 | 条件 | 出す単位 |
|---|---|---|---|
| N-1 | マトリックスに品番が無い | 部品表の「範囲の中」の品番で、T のどれかの仕様で使われているのに、マトリックスに品番が無い | 品番ごとに 1 行 |
| N-2 | 部品表に品番が無い | マトリックスにある品番が、部品表の全体 (絞り込みの外も含む) に無い | 品番ごとに 1 行 |
| N-3 | 名称が違う | 両方にある品番で、6.1 の処理をかけた名称が違う | 品番ごとに 1 行 |
| N-4 | マトリックスに印が無い | 両方にある品番で、部品表では使う仕様なのに、マトリックスでは「なし」 | 品番 × 仕様ごとに 1 行 |
| N-5 | 部品表に登録が無い | 両方にある品番で、マトリックスでは「あり」なのに、部品表ではその仕様で使っていない | 品番 × 仕様ごとに 1 行 |
| N-6 | 員数が違う | 両方で「あり」で、両方に員数があり、数が違う | 品番 × 仕様ごとに 1 行 |

補足:

- 「絞り込みの列」が設定されていないときは、**N-1 は調べない**。部品表には他の部品も入っているので、「範囲の中」が決められないため。調べなかったことをまとめに書く。
- 名称の範囲か名称の列が設定されていないときは、N-3 は調べない。
- N-6 は、値の種類が「員数」で、部品表の員数の列が設定されているときだけ調べる。

警告の種類:

| 記号 | 名前 | 内容 |
|---|---|---|
| W-1 | 品番の重複 | マトリックスに同じ品番が 2 回以上ある |
| W-2 | 仕様の重なり | 複数の見出しが同じ仕様コードに当たっている、または同じ見出しの列が複数ある |
| W-3 | 判断できない値 | 印の一覧に無い値がセルに入っている (△、※1 など)。対象外の見出しの分は出さない |
| W-4 | 品番が数値やエラー | 品番のセルが文字でない、またはエラー値 |
| W-5 | 非表示 | 非表示の行や列を読んだ |
| W-6 | 見出しが空 | 見出しが全部空の列があり、読まなかった |
| W-7 | 部品表の重複 | 部品表に同じ「品番 × 仕様」が 2 行以上ある |
| W-8 | 取り消し線 | 取り消し線のある品番を読んだ |
| W-9 | 品番の形に合わない | 「品番の形」に合わないセルがあり、読まなかった |
| W-10 | 絞り込みの外 | マトリックスの品番が、部品表にはあるが、絞り込みの外にあった (N-2 にはしない) |
| W-11 | 範囲の先に続きがある | 品番の範囲のすぐ先のセルが空でない |

一覧の並び順: 区分 (不一致が先) → 記号 → 表での並び順。

判定:

| 判定 | 条件 |
|---|---|
| 検算が合わない (この結果は使わないこと) | 7.2 の検算で、合わない項目が 1 つでもある |
| 不一致あり | 検算は合い、不一致が 1 件以上 |
| 一致 (警告あり) | 検算は合い、不一致が 0 件で、警告が 1 件以上 |
| 一致 | 検算は合い、不一致も警告も 0 件 |

### 6.9 ファイルの開き方 (`modFile`)

- 読み取り専用で開く (`ReadOnly:=True`、`UpdateLinks:=0`)。
- 開く間だけ `Application.AutomationSecurity = 3` にして、相手のマクロを動かさない。終わったら元に戻す。
- すでに同じファイルが開いているときは、開き直さずにそれを使う。
- 処理が終わっても、開いたファイルは閉じない (利用者が見比べられるように)。

## 7. 本当にチェックできているかを確かめる仕組み

紙と赤ペンのやり方が信用できるのは、**両方の紙の全部の項目に印が付く** からである。印の無い項目が残っていれば、見落としだと目で分かる。
Excel に置き換えても、同じことが言えるようにする。仕組みは 5 つある。

| 仕組み | 何を確かめるか | いつ動くか |
|---|---|---|
| 7.1 消し込み | 見たものの全部に印が付いているか | 照合のたびに毎回 |
| 7.2 検算 | 数のつじつまが合っているか。読みもらした印が無いか | 照合のたびに毎回 |
| 7.3 抜き打ち | 照合が、間違いに本当に気付くか | 照合のたびに毎回 |
| 7.4 自己診断 | ツール全体が正しく動くか | 導入したとき、コードを直したとき |
| 7.5 抜き取り確認 | ツールの「一致」が本当に一致か (人の目) | 使い始めのうちは毎回。慣れたら時々 |

### 7.1 消し込み (赤ペンの代わり)

- **マトリックスの側**: 結果のブックに、マトリックスのシートの写しを作り、ツールが見たセルの全部に色を付ける。

| 色 | 意味 |
|---|---|
| 緑 | 一致 (部品表と合っている)。「あり」同士も、「なし」同士も緑 |
| 赤 | 不一致 |
| 黄 | 判断できない、または警告のある品番 |
| 灰 | 対象外 (比べていない) |
| 水色 | 読んだ見出し |
| 色なし | **ツールが見ていないセル** |

  - 表の中に色なしのセルが残っていれば、範囲の指定が足りない。一目で分かる。
  - 結合セルにまたがって状態が違うときは、悪い方の色が残る (不一致 > 判断できない > 一致 > 対象外)。
  - 写しでは、式を値に直し、条件付き書式を消す (元のファイルへのリンクを残さず、色を見やすくするため)。元のファイルは変えない。
- **部品表の側**: 読んだ全部の行 (品番 × 仕様) に、状態と理由を付けた一覧を出す。「対象外」にも理由を書く (マトリックスに無い仕様、絞り込みの外、など)。
- **セルの一覧**: マトリックスのセルごとの結果を、一覧でも出す (写しが作れなかったときの代わりにもなる)。

### 7.2 検算

結果のブックのシート「検算」に、左と右の数を並べて出す。1 つでも合わなければ、判定は「検算が合わない」になる。

| 記号 | 確かめること |
|---|---|
| K-1 | マトリックス: 品番の数 × 仕様の列の数 = 読んだ値のセルの数 |
| K-2 | マトリックス: 読んだ値のセルの数 = 一致 + 不一致 + 判断できない + 対象外 |
| K-3 | マトリックス: 別の数え方で数えた「あり」の印 = 読み取りで使った「あり」の印 (6.5 の 6) |
| K-4 | 部品表: 品番の列の空でないセルの数 (`COUNTA`) = 読んだ行 + エラーで読まなかった行 |
| K-5 | 部品表: データの行数 = 読んだ行 + 空で飛ばした行 + エラーで読まなかった行 |
| K-6 | 部品表: 共通の形に直した行数 = 一致 + 不一致 + 判断できない + 対象外 |
| K-7 | 突き合わせ: 部品表の「品番 × 仕様」の組 = 一致の組 + 判断できない組 + N-4 の件数 |
| K-8 | 突き合わせ: マトリックスの「あり」の組 = 一致の組 + N-5 の件数 |
| K-9 | 突き合わせ: 一致の組を、部品表の側から数えた数 = マトリックスの側から数えた数 |
| K-10 | 抜き打ち: わざと値を逆にした数 = 照合が気付いた数 (7.3) |
| K-11 | 部品表のファイル: 読んだときの更新日時と大きさ = 今の更新日時と大きさ |
| K-12 | マトリックスのファイル: 同じ |

- K-3 は、「品番が空の行に印がある」「見出しの無い列に印がある」など、**読みもらし** を見つける。読まれていない印の場所も出す。
- K-7〜K-9 は、部品表の側からの数え方と、マトリックスの側からの数え方が、別々の処理で同じになることを確かめる。
- K-11 と K-12 は、読み取った後にファイルが書き換えられていないかを確かめる。

### 7.3 抜き打ち (`modCompare.MutationCheck`)

- 照合が終わった後、**本物のデータのうえで**、マトリックスの値を 1 か所だけわざと逆にして (あり ⇔ なし) 照合し直す。
- 結果が変われば「気付いた」。これを 10 か所 (表の全体からまんべんなく) で繰り返す。
- 変えるのはメモリの中の値だけ。元のファイルも、読み取りの結果も変えない。終わったら値を戻す。
- 試す場所は、結果が必ず変わるはずのセルに限る (仕様コードが 1 つに決まり、同じ組に当たるセルが他に無く、品番が部品表にある)。
- どこを変えて、気付いたかどうかを、シート「検算」に全部書く。

### 7.4 自己診断 (`modTest.RunSelfTest`)

- わざと間違いを入れた作り物のデータを照合して、決まった数の食い違いが見つかることを確かめる (11 章)。
- 同じ中身のマトリックスを、形だけ変えて何通りも作り、**どの形でも同じ結果になること** を確かめる。
- 最後に実行した日時と結果は、照合のたびに結果のブックの「まとめ」に書かれる。

### 7.5 抜き取り確認と、記録

- 結果のブックのシート「抜き取り確認」に、ツールが「一致」としたセルを 10 個 (「あり」と「なし」を半分ずつ、表の全体から) 並べる。
- 人が元の表と見比べて、確認の欄に ○ を付ける。ツールの「一致」を、人の目で裏付けるため。
- 結果のブックの「まとめ」と「設定の控え」には、いつ・だれが・どのファイルを・どの設定で照合したかが残る (C-9)。赤ペンを入れた紙の代わりに、このブックを保管する。

### 7.6 使い始めのおすすめ

- 最初の数件は、今までどおり紙と赤ペンでも確かめて、ツールの結果と同じになるかを見る。
- 違いが出たら、どちらが正しいかを調べ、ツールの側の原因なら自己診断に確かめを足す。

## 8. 出力仕様 (結果のブック)

照合のたびに、新しい Excel ブックを 1 つ作る。ツール用ブックと同じ場所の「照合結果」フォルダに、
`照合結果_(設定名)_(日付_時刻).xlsx` の名前で保存する。見本は `handover/結果の見本.xlsx`。

| シート | 中身 |
|---|---|
| まとめ | 判定。いつ・だれが・ツールの版・自己診断の最後の結果。部品表とマトリックスのファイル、読んだ数。対象の仕様、対象外にした見出し、比べなかった仕様、調べなかった項目。記号ごとの件数。消し込みの数。検算の結果。色の意味 |

## 9. 操作方法

ツール用ブックのシート「操作」にボタンを置く (`SetupTool` が作る)。

| ボタン | マクロ | 動き |
|---|---|---|
| ① 部品表を読む | `Btn_ReadBom` | ファイルを選ぶ → 読取_部品表 を作る |
| ② マトリックスを読む | `Btn_ReadMatrix` | ファイルを選ぶ → 設定の名前を聞く (無ければ形を教える) → 読取_マトリックス を作る |
| ③ 照合する | `Btn_Compare` | 仕様対応表に未設定があれば止まって知らせる → 結果のブックを作って保存する |
| 形を教え直す | `Btn_TeachAgain` | 選んだ設定の範囲を、マウスで選び直す |
| 自己診断 (テスト) を実行 | `Btn_SelfTest` | 11 章のテストを全部行い、シート「テスト結果」に出す |
| テスト用のブックを作る | `Btn_MakeTestFiles` | 操作の練習に使える作り物のデータを `test` フォルダに作る |

エラーのときの表示:

- 何が起きたかを 1 文で。次に利用者が何をすればよいかを 1 文で。
- ツールが自分で出すエラーは番号 20001 (`ERR_TOOL`) で、文をそのまま見せる。それ以外は、番号と内容と場所を添える。

## 10. モジュール構成とデータ構造

### 10.1 モジュール (`vba/`)

| `modLog` | 読み取りの途中の警告をためる | 済 |

| `modSpecMap` | 仕様対応表 (6.7) | 済 |
| `modCompare` | 照合の本体 (6.8) と抜き打ち (7.3) | 済 |

決まり:

- 全部のモジュールの先頭に `Option Explicit` を書く。

- 辞書は `NewDict()` で作り、書き換えは `DictSet` を通す。辞書には数と文字だけを入れ、配列は入れない。
- 変数の名前に、VBA が先に使っている言葉 (`Base`、`Val`、`Rows` など) を使わない。

## 12. ここまでで分かったこと

LibreOffice (Excel と似たソフト) の、VBA をそのまま動かす機能を使って、コードを実際に動かして確かめた。自己診断は 42 項目すべて合格した。

| No | 分かったこと | 対応 |
|---|---|---|
| 1 | 結合セルは、左上のセルだけに値がある | 空のセルだけを調べて、結合の左上の値を当てる (6.4) |
| 2 | VBA の編集画面は、一部の記号を保存できない | 記号の一覧はシートに置く。コードでは番号で書く (6.1) |
| 3 | 1 セルずつ読むと遅い | 値は配列でまとめて読む |
| 4 | 品番が数値として入っていると、先頭の 0 や長い桁が壊れる | 表示されている文字を使い、警告を出す |
| 5 | 文字をそのままセルに書くと、Excel が数値や日付に変えてしまう | 書く前に、セルの書式を文字列にする (`modUtil.WriteTable`) |
| 6 | 開いたファイルのマクロが勝手に動くことがある | `modFile.OpenReadOnly` のとおりに開く |
| 7 | 全角を半角にする処理は、PC の言語の設定で動きが変わる | `StrConv` に `1041` (日本語) を指定する |
| 8 | `Base` や `Val` は、VBA が先に使っている言葉 | 変数の名前に使わない (10.1) |
| 9 | Power Query では結合の情報が読めない | 結合セルを正しく扱うために VBA を選んだ |
| 10 | 検算が、作っている途中の不具合を実際に見つけた (数の取り出し方が原因で、足し算の結果がずれていた) | 検算と自己診断は、コードを直すたびに必ず通す。数は先に変数へ取り出してから計算する |

**LibreOffice で確かめられなかったこと (本物の Excel で最初に確かめること):**

- `modMain` の全部 (ファイルを選ぶ画面、マウスで範囲を選ぶ画面、知らせる画面)。
- `modSetup` のボタン作り。
- `modDict` の 2 行 (`Scripting.Dictionary` を作る所)。
- 結果のブックの保存 (`SaveAs`)。
- セルのエラー値 (`#N/A` など) の扱い。
- 見た目 (列の幅、色) の細かい違い。

| S-2 | 食い違いのセルに、コメントで理由を付ける |
| S-3 | 書き間違いの候補を出す (1 文字だけ違う品番を「もしかして」として並べる) |
| S-4 | 「名称 × 仕様」の表で、セルに品番を書く形のマトリックス (F-12) に対応する |
| S-5 | 複数のマトリックスを続けて照合する。設定を他の人と共有する |
| S-6 | 部品表が横持ち (4.1 の (b)) のときに、マトリックスと同じ読み方で読む |
| S-7 | 形を教える所を、専用の画面 (フォーム) にする |

### 13.3 今の制限

- 本物の Excel では、まだ一度も動かしていない (12 章)。
- マトリックスの形は、人が最初に 1 回教える必要がある。
- 部品表とマトリックスが **同じように間違っている** 場合は、見つけられない。
- 色、塗りつぶし、コメント、図形、テキストボックスに書かれた内容は読まない。
- 行が増えたマトリックスは、範囲を選び直す必要がある (ツールが気付いて知らせる)。
- 自己診断を実行すると、読み取り済みのデータ (読取_…) は消える。設定は消えない。
