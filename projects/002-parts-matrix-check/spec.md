## 1. 目的

**部品表** と **品番マトリックス** の中身が合っているかを、Excel の上で自動で確かめる。

| 言葉 | 意味 |
|---|---|
| 部品表 | システムに登録されている部品の一覧。部品名称、品番、使われている車の仕様などが入っている。**形は一律** |
| 品番マトリックス (以下、マトリックス) | 事務所で使いやすいように作った Excel の表。片方の軸に品番、もう片方の軸に車の仕様が並ぶ。**形は設計者や部品の種類によってばらばら**。セルの結合もある |
| 仕様 | 車の作り分けの単位 (グレード、駆動方式など)。部品がどの車に使われるかを表す |
| 照合 | 2 つの表を突き合わせて、食い違いを探すこと |

- 入力: 部品表のファイル 1 つと、マトリックスのファイル 1 つ (1 シート)。
- 出力: 食い違いの一覧と、件数のまとめ。
- 使う人: マトリックスを作る設計者、または確認する人。
- 書かれている内容は、2 つの表でほとんど同じ。**難しいのは形が違うこと**。この文書の中心は、ばらばらな形のマトリックスをどう読むかにある。

## 2. 絶対条件

| No | 条件 | 内容 |
|---|---|---|
| C-1 | **外部通信の禁止** | 実行中は一切の外部通信をしない。クラウドのサービス、Web API、テレメトリ、自動更新、オンラインのデータ取得はすべて禁止 |
| C-2 | **ローカル完結** | 入力の読み込みから出力まで、すべて手元の PC の中で完結させる |
| C-3 | オフラインで導入できること | インターネットにつながらない PC へ導入する手順を README に書く (部品を持ち込んで入れる手順) |
| C-4 | 社内データを入れない | 本物の部品表やマトリックスはリポジトリに入れない。テストには自分で作ったデータを使う |
| C-5 | 言語 | 画面の表示、エラー、説明は日本語。専門用語には短い説明を添える |
| C-6 | **元のファイルを書き換えない** | 部品表とマトリックスは読み取り専用で開く。保存もしない。色を付けたいときは写しに付ける |
| C-7 | **追加の部品を入れない** | Excel に最初から入っている VBA の機能だけで作る。追加のソフト、アドイン、参照設定の追加は使わない |
| C-8 | **黙って捨てない** | 読めなかったセル、対象から外した行や列は、必ず結果の一覧に出す。「何も出ない = 合っている」と言える状態を保つ |

C-1 を VBA で守るための決まり:

- 使ってはいけないもの: `WinHttp`、`MSXML2.XMLHTTP`、`InternetExplorer`、Web クエリ、`Shell` による外部プログラムの起動、Windows API の `Declare`。
- ファイルを開くときは `UpdateLinks:=0` を付ける (他のファイルへのリンクを更新させない)。
- 開く相手のファイルに入っているマクロは動かさない (6.9 の見本)。

- メールや Web から受け取ったファイルは、Windows が印を付けてマクロを止めることがある。その場合の解除手順を README に書く (ファイルのプロパティ →「許可する」)。

## 4. 入力仕様

### 4.1 部品表

- システムから出した一覧。形は一律。
- 見出しの行が 1 行あり、その下に 1 行ずつ部品のデータが並ぶ。
- 列の名前と並びは **未確認** (12.1 の Q-01、Q-02)。そのため列の場所は、コードに書かず設定シートに持たせる (6.2)。
- 仕様の持ち方は、次の 3 つのどれかと想定する。第一段階は (a) と (c) に対応する。

| 型 | 仕様の持ち方 | 例 |
|---|---|---|
| (a) 縦持ち | 1 行が「品番 1 つ × 仕様 1 つ」 | 同じ品番の行が、仕様の数だけ並ぶ |
| (b) 横持ち | 仕様ごとに列があり、印や員数が入る | 部品表そのものがマトリックスの形 |
| (c) まとめ書き | 1 つのセルに仕様が複数入る | `S1,S2,S3` |

(b) だった場合は、部品表もマトリックスと同じ読み方 (6.3〜6.5) で読む。

### 4.2 マトリックス

決まった形は無い。ただし次のことは共通と想定する。

- Excel の表である。
- 片方の軸に品番、もう片方の軸に車の仕様が並ぶ。
- 品番と仕様が交わるセルに、使うかどうかの印 (○ など) か、員数 (使う個数) が入る。

形の違いとして想定するもの:

| No | 違い | 例 |
|---|---|---|
| F-1 | 品番の向き | 品番が縦に並ぶ表と、横に並ぶ表がある |
| F-2 | 表の始まる場所 | 上に題名や日付の行があり、表は途中から始まる |
| F-3 | 仕様の見出しが何段もある | 上の段がグレード、下の段が駆動方式、など |
| F-4 | 見出しのセル結合 | 上の段の「STD」が、下の段の 2 列分にまたがって結合されている |
| F-5 | 見出しの空欄 | 結合せずに、左と同じ値のセルを空欄にしている |
| F-6 | 値のセル結合 | ○ が 1 つ、複数の仕様の列にまたがって結合されている |
| F-7 | 途中の区切り | 品番の並びの途中に、空行や小見出しの行がある |
| F-8 | 関係ない列 | 備考、材質、図番など、仕様ではない列が混ざる |
| F-9 | 品番の書き方 | 全角と半角、ハイフンの有無、前後の空白、1 つのセルに改行で 2 つ |
| F-10 | 印の種類 | ○、●、◎、レ、数字、－、× など |
| F-11 | 見た目で意味を表す | 取り消し線、塗りつぶし、非表示の行や列 |

形の例 (同じ中身を 2 通りに書いたもの):

```
例 1: 品番が縦。見出しが 2 段で、上の段が結合されている

         |            |    STD    |    DX     |
  名称   |  品番      | 2WD | 4WD | 2WD | 4WD |
  -------+------------+-----+-----+-----+-----+
  部品A  | AB123-0010 |  ○  |  ○  |     |     |
  部品B  | AB123-0020 |     |     |  ○  |  ○  |

例 2: 品番が横。仕様が縦

               | 部品A      | 部品B      |
               | AB123-0010 | AB123-0020 |
  -----+-------+------------+------------+
  STD  | 2WD   |     ○      |            |
       | 4WD   |     ○      |            |
  DX   | 2WD   |            |     ○      |
       | 4WD   |            |     ○      |
```

## 5. 考え方と処理の流れ

### 5.1 基本の考え方

| No | 考え方 | 理由 |
|---|---|---|
| P-1 | **両方を同じ形 (共通の形) に直してから比べる** | 形の違いを読み取りの所だけに閉じ込める。比べる処理は 1 つで済む |
| P-2 | **マトリックスの形は人が教え、ツールが覚える** | 形がばらばらなので、自動で当てると読み違える。確認用のツールが読み違えると「合っている」と誤って伝えてしまう |
| P-3 | **教えるのは 3 か所だけ** | 品番の範囲、名称の範囲、仕様の見出しの範囲。マウスで選ぶ。値のセルの場所は、この 3 つから自動で決まる |
| P-4 | **読み取った結果を必ず見せる** | 共通の形に直したものをシートに書き出す。人が「正しく読めたか」を確かめられる |
| P-5 | **段階の間はシートで受け渡す** | 読み取り、照合、結果の各段階を別々に作って確かめられる。Copilot で 1 つずつ作りやすい |

共通の形とは、「1 行 = 品番 1 つ × 仕様 1 つ」の縦長の一覧のこと。

```
  品番        | 名称  | 仕様        | 値
  ------------+-------+-------------+----
  AB123-0010  | 部品A | STD / 2WD   | あり
  AB123-0010  | 部品A | STD / 4WD   | あり
  AB123-0020  | 部品B | DX / 2WD    | あり
  AB123-0020  | 部品B | DX / 4WD    | あり
```

### 5.2 処理の流れ

```
① 部品表を読む
     部品表のファイル → [設定_部品表 に従って読む] → シート「読取_部品表」

② マトリックスの形を教える (初めての形のときだけ)
     マウスで 3 か所を選ぶ → シート「設定_マトリックス」に保存

③ マトリックスを読む
     マトリックスのファイル → [設定に従って読む。結合セルをほどく] → シート「読取_マトリックス」

④ 仕様の呼び名を合わせる
     マトリックスの見出しの文字 ↔ 部品表の仕様コード → シート「仕様対応表」
     (自動でうめる。うまらない所だけ人が書く)

⑤ 照合する
     読取_部品表 と 読取_マトリックス を比べる → シート「結果_まとめ」「結果_一覧」
```

2 回目からは ② と ④ がほぼ不要になる。設定と対応表を覚えているため。

## 6. 処理の詳しい仕様

### 6.1 文字のそろえ方 (比べるための下ごしらえ)

比べる前に、両方の文字へ同じ処理をかける。元の文字は別に残し、画面や結果には元の文字を出す。

品番にかける処理 (この順番で行う):

1. セルの中の改行を取る (1 セルに複数の品番を許す設定のときは、改行で分けてから以下を行う)。
2. 全角の英数字と記号を半角にする (`StrConv(s, vbNarrow, 1041)`)。
3. 英字を大文字にする (`UCase`)。
4. 半角と全角の空白をすべて取る。
5. 「ハイフンとみなす文字」を半角の `-` に置き換える。
6. 設定「ハイフンを無視する」が「する」なら、`-` をすべて取る (既定は「しない」)。

名称にかける処理: 1〜4 だけを行う。5 と 6 は行わない (名称の長音「ー」を壊さないため)。

仕様の文字にかける処理: 1〜4 だけを行う。

決まり:

- 「ハイフンとみなす文字」「あり を表す印」「なし を表す印」は、**シート「設定_文字」に 1 セル 1 文字で置く**。コードの中に直接書かない。
  - 理由: VBA の編集画面は、一部の記号 (✓ など) を表示も保存もできない。
- どうしてもコードに記号を書くときは、`ChrW(&H25CB)` のように番号で書く。
- 品番のセルが数値だったとき (先頭の 0 が消えた、桁が丸められた、などのおそれ) は、表示されている文字 (`.Text`) を使い、警告 W-4 を出す。`.Text` が `#` だけのときは `Format$(値, "0")` を使う。
- セルがエラー値 (`#N/A` など) のときは読まずに、警告 W-4 を出す。

### 6.2 部品表の読み取り

設定はシート「設定_部品表」に持つ。列は見出しの文字で指定する (列の並びが変わっても動くように)。

| 設定の項目 | 例 | 説明 |
|---|---|---|
| 見出しの行 | 1 | 見出しがある行の番号 |
| 品番の列 | 品番 | 見出しの文字 |
| 名称の列 | 部品名称 | 見出しの文字 |
| 仕様の列 | 仕様コード | 見出しの文字。複数あるときはカンマで並べる。複数のときは値を ` / ` でつないで 1 つの仕様コードにする |
| 仕様の区切り文字 | , | 1 セルに仕様が複数入るとき (4.1 の (c))。空欄なら分けない |
| 員数の列 | 員数 | 空欄可。空欄なら員数は比べない |
| 絞り込みの列 | 品番 | 空欄可。そのマトリックスが扱う部品だけに絞るための列 |
| 絞り込みの値 | AB123* | `Like` の書き方。絞り込みの列がこの形に合う行だけを「範囲の中」とする |

手順:

1. ファイルを選ぶ画面を出す (`Application.GetOpenFilename`)。読み取り専用で開く (6.9)。
2. 使われている範囲の値を、まとめて配列に読む (1 セルずつ読むと遅い)。
3. 見出しの行から、各設定の列を探す。見つからない列があれば、その名前を表示して止まる。
4. 1 行ずつ、品番・名称・仕様・員数を取り出し、6.1 の処理をかける。
5. 品番が空の行は飛ばす。飛ばした行数をまとめに出す。
6. 「読取_部品表」に書き出す (9.2)。絞り込みに合うかどうかも「範囲の中」の列に書く。
7. 同じ「品番 × 仕様」が 2 行以上あれば、警告 W-7 を出す。

### 6.3 マトリックスの読み取り設定

設定はシート「設定_マトリックス」に、**1 つの表につき 1 行** で持つ。

| 設定の項目 | 例 | 説明 |
|---|---|---|
| 設定名 | ブラケット前側 | 利用者が付ける名前。次回はこの名前で呼び出す |
| シート名 | Sheet1 | 対象のシート |
| 品番の向き | 縦 | 縦 = 品番が上から下へ並ぶ。横 = 左から右へ並ぶ |
| 品番の範囲 | C6:C40 | 品番が並ぶセル。見出しは含めない |
| 名称の範囲 | B6:B40 | 空欄可。品番の範囲と同じ長さ |
| 仕様の見出しの範囲 | E3:P5 | 仕様の見出し。何段あってもよい |
| 値の種類 | 印 | 印 = 使う/使わない。員数 = 個数 |
| 見出しの空欄の引き継ぎ | する | F-5 への対応 (6.4) |
| 1 セルに複数の品番 | 分けない | 「分ける」なら改行で分ける |
| 品番の形 | (空欄) | 空欄可。`Like` の書き方。合わないセルは品番として読まず、警告 W-9 を出す |
| 最後に使った日 | 2026-11-11 | ツールが書く |

範囲の決まり (品番の向きが「縦」のとき):

- 品番の範囲は「n 行 × 1 列以上」。2 列以上のときは、左から順につないで 1 つの品番にする (品番が 2 つの列に分かれている表のため)。
- 仕様の見出しの範囲は「k 行 × m 列」。この m 列が仕様の列になる。
- **値のセルは「品番の範囲の行」と「見出しの範囲の列」が交わる所**。別に指定しない。
- 見出しの範囲の行は、品番の範囲の行と重なってはいけない。列も重なってはいけない。重なっていたら保存せずに知らせる。

品番の向きが「横」のときは、上の「行」と「列」を入れ替えて読む。処理は 1 つにまとめ、縦横の入れ替えは読み取りの入口だけで行う。

1 枚のシートに表が 2 つ以上あるときは、表ごとに設定を 1 行ずつ作る。

### 6.4 結合セルと空欄の扱い

結合されたセルは、Excel の中では **左上のセルだけに値があり、残りは空** になっている。これをそのまま読むと、値が無いと誤解する。次のように扱う。

| 場所 | 扱い |
|---|---|
| 見出し (F-4) | 結合されていれば、結合範囲の左上の値を、範囲の全部のセルの値とみなす |
| 名称 | 同じ。縦に結合された名称は、その範囲の全部の品番の名称とみなす |
| 品番 | 結合されていれば、**結合範囲で 1 つの品番** として読む (品番の行を増やさない)。値のセルは、その範囲の行すべてを見る |
| 値 (F-6) | 結合されていれば、結合範囲の左上の値を、**範囲にかかる全部の「品番 × 仕様」に当てはめる** |

見本 (結合セルの値を取る):

```vb
' 結合セルなら、結合範囲の左上のセルの値を返す
Function CellValueMerged(ByVal c As Range) As Variant
    If c.MergeCells Then
        CellValueMerged = c.MergeArea.Cells(1, 1).Value2
    Else
        CellValueMerged = c.Value2
    End If
End Function
```

見本 (範囲の中に結合セルがあるかを一度で調べる。無ければ配列だけで速く読める):

```vb
' Range.MergeCells は、全部が結合なら True、結合なしなら False、混ざっていれば Null を返す
Function HasMerge(ByVal rng As Range) As Boolean
    Dim m As Variant
    m = rng.MergeCells
    If IsNull(m) Then
        HasMerge = True
    Else
        HasMerge = CBool(m)
    End If
End Function
```

見出しの空欄の引き継ぎ (F-5。設定が「する」のときだけ):

- 対象は、**一番下の段以外** の見出しのセル。
- セルが空で、結合もされていないとき、左隣の列の値を引き継ぐ。
- ただし引き継ぐのは、**一つ上の段の値が左隣と同じ間だけ**。上の段が変わったら引き継がない。
- 一番下の段は引き継がない (空欄は空欄のまま)。
- 品番の向きが「横」のときは、「左」を「上」に読み替える。

列ごとの「見出しの文字」の作り方:

1. その列の見出しのセルを、上の段から順に取る (結合と引き継ぎを反映した値)。
2. 空の段は飛ばす。上の段と同じ文字が続くときは 1 つにする。
3. 残った文字を ` / ` でつなぐ。例: `STD / 2WD`
4. 全部の段が空の列は読まない。警告 W-6 を出す。

### 6.5 マトリックスの読み取り手順

1. ファイルを選ぶ画面を出し、読み取り専用で開く (6.9)。
2. 設定を選ぶ。無ければ 6.6 の画面で作る。
3. 設定の確かめをする。
   - シートがあるか。範囲がシートの中に収まっているか。
   - 品番の範囲のすぐ先 (縦なら下、横なら右) のセルが空でなければ、「行が増えたかもしれません。範囲を選び直しますか」と聞く。
4. 仕様の列ごとに「見出しの文字」を作る (6.4)。作った見出しの文字は、「あり」が 1 つも無い列の分も含めて、全部を「仕様対応表」に足す (その設定名でまだ無いものだけ。仕様コードは空欄で足す)。
5. 品番の範囲を先頭から順に読む。
   - 品番のセルが空なら、その行は飛ばす (F-7)。飛ばした行は警告にはせず、まとめに行数を出す。
   - 「品番の形」が設定されていて、品番キー (6.1 の処理をかけた品番) が合わなければ、読まずに警告 W-9 を出す。
   - 行や列が非表示なら、読んだうえで警告 W-5 を出す (F-11)。
   - 品番の文字に取り消し線があれば、読んだうえで警告 W-8 を出す。`Font.Strikethrough` が `Null` (一部だけ取り消し線) のときも同じ。
6. 品番ごとに、仕様の列のセルを読む (結合を反映した値)。値は前後の空白を取り、6.1 の 2 と 4 の処理をかけてから、印の一覧と比べる (一覧の側にも同じ処理をかける)。次のように判定する。

| 値の種類 | セルの値 | 判定 |
|---|---|---|
| 印 | 「あり を表す印」のどれか | あり |
| 印 | 空、または「なし を表す印」のどれか | なし |
| 印 | それ以外 | 判断できない。警告 W-3 |
| 員数 | 0 より大きい数 | あり (員数 = その数) |
| 員数 | 空、0、または「なし を表す印」 | なし |
| 員数 | 「あり を表す印」 | あり (員数は不明。員数は比べない) |
| 員数 | それ以外 | 判断できない。警告 W-3 |

7. 「読取_マトリックス」に、**「あり」と「判断できない」の分だけ** 書き出す (9.2)。「なし」は書かない。
   - ただし、どの仕様も「なし」だった品番は、仕様を空にした行を 1 行だけ書く (品番があること自体は記録するため)。
8. 同じ品番が 2 回以上出たら、警告 W-1 を出し、仕様は合わせたもの (どちらかで「あり」なら「あり」) として扱う。
9. 読み終わったら、「品番 ○ 件、仕様の列 ○ 列、あり ○ 件を読みました」と表示する。

### 6.6 マトリックスの形を教える画面

`Application.InputBox` の範囲を選ぶ機能 (`Type:=8`) を使う。専用の画面 (フォーム) は第一段階では作らない。

順番:

1. 「品番が並んでいるセルを選んでください (見出しは含めない)」
2. 「部品名称が並んでいるセルを選んでください (無ければキャンセル)」
3. 「仕様の見出しのセルを選んでください (何段あっても全部)」
4. 品番の向きは、1 で選んだ範囲が縦長か横長かで決める。1 行 1 列のときだけ利用者に聞く。
5. 値の種類 (印 / 員数) を聞く。
6. 設定名を聞いて、「設定_マトリックス」に保存する。
7. 保存の前に、6.3 の範囲の決まりを確かめる。

見本 (範囲を選んでもらう):

```vb
' キャンセルされたら Nothing を返す
Function AskRange(ByVal prompt As String) As Range
    On Error Resume Next
    Set AskRange = Application.InputBox(prompt:=prompt, Type:=8)
    On Error GoTo 0
End Function
```

### 6.7 仕様対応表 (呼び名を合わせる)

マトリックスの見出しの文字と、部品表の仕様コードは、呼び名が違うことがある。対応をシート「仕様対応表」に持つ。

| 列 | 例 | 説明 |
|---|---|---|
| 設定名 | ブラケット前側 | どのマトリックスの設定か |
| 見出しの文字 | STD / 2WD | 6.4 で作った文字 |
| 仕様コード | S1 | 部品表の側の呼び名。空欄は「未設定」 |
| 対象外 | (空欄) | 「対象外」と書くと、その列は比べない (備考の列など。F-8) |

決まり:

- 1 つの見出しが複数の仕様コードに当たるときは、**行を複数書く** (見出し 1 つ → 仕様コード 2 つなら 2 行)。
- 自動でうめる: 見出しの文字と仕様コードが、6.1 の処理をかけた後で同じなら、その仕様コードを入れる。
- 自動でうまらなかった見出しは、仕様コードを空欄のままにして一覧に足す。
- **未設定の見出しが 1 つでも残っていたら、照合を始めない**。未設定の一覧を見せて、仕様コードを書くか「対象外」と書くように頼む。
  - 理由: 黙って飛ばすと、比べていない列があるのに「合っている」と見えてしまう (C-8)。
- 複数の見出しが同じ仕様コードに当たっているときは、警告 W-2 を出す (どちらかで「あり」なら「あり」として扱う)。
- 対象外にした見出しは、まとめに一覧で出す。その見出しの行は、照合にも警告にも使わない。

### 6.8 照合

準備:

- B = 部品表の「品番 × 仕様コード」の集まり (読取_部品表 から)。
- M = マトリックスの「品番 × 仕様コード」の集まり (読取_マトリックス を仕様対応表で仕様コードに直したもの)。「判断できない」の分は入れない。
- T = 対象の仕様 = 仕様対応表でマトリックスの見出しに対応づけた仕様コードの全部。
- 部品表の「T に入らない仕様」は比べない。その仕様コードの一覧をまとめに出す。

食い違いの種類 (不一致):

| 記号 | 名前 | 条件 | 出す単位 |
|---|---|---|---|
| N-1 | マトリックスに品番が無い | 部品表の「範囲の中」の品番で、T のどれかの仕様で使われているのに、マトリックスに品番が無い | 品番ごとに 1 行 |
| N-2 | 部品表に品番が無い | マトリックスにある品番が、部品表の全体 (絞り込みの外も含む) に無い | 品番ごとに 1 行 |
| N-3 | 名称が違う | 両方にある品番で、6.1 の処理をかけた名称が違う | 品番ごとに 1 行 |
| N-4 | マトリックスに印が無い | 両方にある品番で、部品表では使う仕様なのに、マトリックスでは「なし」 | 品番 × 仕様ごとに 1 行 |
| N-5 | 部品表に登録が無い | 両方にある品番で、マトリックスでは「あり」なのに、部品表ではその仕様で使っていない | 品番 × 仕様ごとに 1 行 |
| N-6 | 員数が違う | 両方で「あり」で、両方に員数があり、数が違う | 品番 × 仕様ごとに 1 行 |

補足:

- 「絞り込みの列」が設定されていないときは、**N-1 は調べない**。部品表には他の部品も入っているので、「範囲の中」が決められないため。調べなかったことをまとめに書く。
- N-2 で、品番が部品表の「絞り込みの外」にあったときは、N-2 にせず警告 W-10 にする。
- 名称の範囲が設定されていないときは、N-3 は調べない。
- N-6 は、値の種類が「員数」で、部品表の員数の列が設定されているときだけ調べる。

警告の種類:

| 記号 | 名前 | 内容 |
|---|---|---|
| W-1 | 品番の重複 | マトリックスに同じ品番が 2 回以上ある |
| W-2 | 仕様の重なり | 複数の見出しが同じ仕様コードに当たっている |
| W-3 | 判断できない値 | 印の一覧に無い値がセルに入っている (△、※1 など) |
| W-4 | 品番が数値やエラー | 品番のセルが数値、またはエラー値 |
| W-5 | 非表示 | 非表示の行や列を読んだ |
| W-6 | 見出しが空 | 見出しが全部空の列があり、読まなかった |
| W-7 | 部品表の重複 | 部品表に同じ「品番 × 仕様」が 2 行以上ある |
| W-8 | 取り消し線 | 取り消し線のある品番を読んだ |
| W-9 | 品番の形に合わない | 「品番の形」に合わないセルがあり、読まなかった |
| W-10 | 絞り込みの外 | マトリックスの品番が、部品表の絞り込みの外にあった |

判定:

| 判定 | 条件 |
|---|---|
| 一致 | 不一致が 0 件で、警告も 0 件 |
| 一致 (警告あり) | 不一致が 0 件で、警告が 1 件以上 |
| 不一致あり | 不一致が 1 件以上 |

### 6.9 ファイルの開き方

見本 (読み取り専用で開く。相手のマクロは動かさない。リンクは更新しない):

```vb
' 開けなかったときは Nothing を返す (呼ぶ側で確かめる)
Function OpenReadOnly(ByVal path As String) As Workbook
    Dim sec As Long
    sec = Application.AutomationSecurity
    Application.AutomationSecurity = 3      ' 3 = 開く相手のマクロを無効にする
    On Error GoTo Finally
    Set OpenReadOnly = Workbooks.Open(Filename:=path, ReadOnly:=True, UpdateLinks:=0)
Finally:
    Application.AutomationSecurity = sec
End Function
```

- すでに同じファイルが開いているときは、開き直さずにそれを使う。
- 処理が終わっても、開いたファイルは閉じない (利用者が結果のリンクから飛べるように)。閉じるときは保存しない。
- 「保護ビュー」で開かれたファイルは VBA から読めない。その場合は「編集を有効にしてから、もう一度実行してください」と表示する。

## 8. 操作方法

ツール用ブックのシート「操作」にボタンを置く。

| ボタン | 動き |
|---|---|
| ① 部品表を読む | ファイルを選ぶ → 読取_部品表 を作る |
| ② マトリックスを読む | ファイルを選ぶ → 設定を選ぶ (無ければ形を教える) → 読取_マトリックス を作る |
| ③ 照合する | 仕様対応表を自動でうめる → 未設定があれば止まって知らせる → 結果を作る |
| 形を教え直す | 選んだ設定の範囲を、マウスで選び直す |
| テストを実行 | 10 章のテストを全部行い、合格と不合格を一覧に出す |

エラーのときの表示:

- 何が起きたかを 1 文で。次に利用者が何をすればよいかを 1 文で。
- 例: 「部品表に『品番』という見出しが見つかりません。シート『設定_部品表』の『品番の列』を確かめてください。」
- 予想していないエラーは、エラーの番号と起きた処理の名前を添える。
- 途中で止まっても、`ScreenUpdating` や `AutomationSecurity` などの設定は必ず元に戻す。

## 11. 試作で分かったこと

## 12. 残課題

### 12.1 確認が必要なこと (必須)

実物の表を見ないと決められないこと。答えが出るまでは「仮の扱い」で進める。

| No | 確認すること | なぜ必要か | 仮の扱い |
|---|---|---|---|
| Q-01 | 部品表の仕様の持ち方は、4.1 の (a) (b) (c) のどれか | 部品表の読み方が変わる | (a) 縦持ち |
| Q-02 | 部品表のファイルの種類 (Excel か CSV か)、見出しの行の場所、列の名前 | 設定_部品表 の初期値になる | Excel。見出しは 1 行目 |
| Q-03 | マトリックスの値は印か員数か。「名称 × 仕様」の表で、セルに品番そのものを書く形は無いか | 後者は読み方が別になる | 印か員数。品番を書く形は対象外 |
| Q-04 | 仕様の呼び名は、部品表とマトリックスで同じか。マトリックスの 1 列が、部品表の複数の仕様に当たることはあるか | 仕様対応表を人が書く量が決まる | 違うことがある。1 対多もある |
| Q-05 | 部品表から「そのマトリックスが扱う部品」だけを選ぶ手がかりはあるか (列の値、品番の前半など) | N-1 (マトリックスの書きもれ) を調べるのに必要 | 品番の前半で絞る |
| Q-06 | 軸は「車の仕様」でよいか (依頼の文では「各社の仕様」とも書かれていた) | 軸の意味が変わると、対応表の作りが変わる | 車の仕様 |
| Q-07 | 名称も比べるか。略した書き方が多いか | 多いと N-3 だらけになる | 比べる。多ければ設定で止める |

| Q-13 | 結果は一覧だけでよいか。マトリックスの写しに色を付けたいか | 第二段階の優先順位が決まる | 一覧だけ |

### 12.2 次の段階の候補

| No | 内容 |
|---|---|
| S-1 | **形の自動提案**。部品表の品番と同じ文字が一番多く並ぶ列 (または行) を「品番の範囲」の候補として示す。仕様の見出しも、部品表の仕様コードや対応表に出てくる文字から候補を示す。人は確かめて直すだけになる |
| S-2 | マトリックスの写しを作り、食い違いのセルに色とコメントを付ける |
| S-3 | 書き間違いの候補を出す (1 文字だけ違う品番を「もしかして」として並べる) |
| S-4 | 「名称 × 仕様」の表で、セルに品番を書く形のマトリックスに対応する |
| S-5 | 複数のマトリックスを続けて照合する。設定を他の人と共有する |
| S-6 | 部品表が横持ち (4.1 の (b)) のときに、マトリックスと同じ読み方で読む |

### 12.3 今の制限

- マトリックスの形は、人が最初に 1 回教える必要がある。
- 部品表とマトリックスが **同じように間違っている** 場合は、見つけられない。
- 色、塗りつぶし、コメント、図形、テキストボックスに書かれた内容は読まない。
- 行が増えたマトリックスは、範囲を選び直す必要がある (ツールが気付いて聞く)。
- VBA の見本は Excel で動かして確かめていない。
