## 提案 (構想書に書いたが、まだ了承をもらっていないこと)

| No | 提案 | 理由 |
|---|---|---|
| P-01 | 言語は Excel VBA。追加のソフトは使わない | 依頼でも VBA の見込みだった。結合セルの情報を読めるのは VBA。Power Query や関数だけでは結合が読めない |
| P-02 | 両方を「品番 × 仕様」の縦長の一覧に直してから比べる | 形の違いを読み取りの所だけに閉じ込められる |
| P-03 | マトリックスの形は、人がマウスで 3 か所を教え、ツールが覚える | 形がばらばらなので、自動で当てると読み違える。確認用のツールが読み違えるのは危ない |
| P-04 | 形の自動提案は第二段階にする | まず確実に動く方式を作る。自動提案は、その上に足せる |
| P-05 | 仕様の呼び名の違いは「仕様対応表」で合わせる。未設定が残っていたら照合を始めない | 黙って飛ばすと、比べていないのに「合っている」と見えてしまう |
| P-06 | 元のファイルは読み取り専用で開き、書き換えない。結果は別のシートに出す | 大事な元データを壊さない |
| P-07 | マクロはツール用のブック 1 つに入れる。マトリックスの側にはマクロを入れない | 設計者ごとのファイルを変えずに済む |
| P-08 | 読み取った結果を必ずシートに見せる | 正しく読めたかを人が確かめられる。Copilot で 1 段階ずつ作りやすい |
